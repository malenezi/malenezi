## Scenario and path

**Path B - Guided scenario B2: Internal IT Help Desk for Employees.** Employees send support tickets about access, devices and software. The assistant drafts text; a technician reviews every message before sending it. This is an invented training scenario, with the seven supplied facts copied unchanged.

## Ten tasks - exactly five selected

The original task names and goals are retained from the guided scenario. Classification suggests a label; it does not actually route a ticket.

| No. | Task | Goal | Built |
|---|---|---|---|
| 1 | Resolve a support ticket | Write a clear reply to an employee’s support ticket using only the Help Desk Facts. | Yes |
| 2 | Shorten a ticket thread | Summarize a long ticket thread in three lines for the next technician. | Yes |
| 3 | Route tickets to teams | Label each ticket as Access, Hardware, Software, Network or Other. | Yes |
| 4 | Explain it simply | Rewrite a technical answer in plain language for a non-technical employee. | Yes |
| 5 | Bilingual status message | Translate an approved service status message between Arabic and English without changing any time or fact. | No - outside selected scope |
| 6 | Planned maintenance notice | Write a short notice about planned maintenance with the date, time and what to do. | No - outside selected scope |
| 7 | Fix-it steps | Turn a known fix into short numbered steps an employee can follow alone. | No - outside selected scope |
| 8 | Clean a ticket before pasting | Replace names, usernames, emails and device codes in a ticket with codes before it goes to an AI tool. | No - outside selected scope |
| 9 | Self-help cheat sheet | Turn five common problems and their fixes into a short self-help list. | No - outside selected scope |
| 10 | Senior technician handoff | Write a short note for the senior technician when a ticket needs a person’s decision. | Yes |

## What is included

- Exactly five versioned templates using RACE, fixed output formats, the same five language modes, variable defaults and embedded safety rules.
- One shared block of seven IT facts and one file containing the five adapted Day 4 responsible-use rules.
- Fifteen recorded in-session applications: two fills and one edge case per template, with full prompts, outputs, word counts and CHECK evidence.
- A six-page test report and a separate project portfolio containing the components and outputs.
- A requirement checklist that distinguishes completed local work from public GitHub publishing and evidence requirements.

## Evidence and review scope

ChatGPT (Codex) applied the filled templates in this project conversation and preserved the responses in the run records. There were no independent model/API calls and no live IT operations. Scores are AI-assisted rubric self-assessments, not approval by an instructor, organization or human technician. Current scores are 5/5, 6/6 and 4/5; all five templates remain Needs work because a native human wording review and genuine AI-tool screenshots are outstanding. Before operational use, a responsible technician must review wording and the current facts and an organization must approve its AI tool.

See [evidence provenance](PE_Library_Meshal/evidence/PROVENANCE.md) for the exact kind of visual evidence provided. A rendered transcript is never described as a screenshot of an AI tool.
