    Curriculum Map — LO1–LO8 traceability matrix¶

    SDA-AIE-311's eight capstone learning objectives (final_capstone_project.md, "Mandatory" requirements 1–8), each traced to the module(s) that teach it, the lab(s) that build it, the exact repository paths that implement it, the test/verification that proves it, and the benchmark(s) that measure it. Every path below exists in this repository and has been run — see each lab's own README "Expected outputs" section for the full numbers.

    LO Objective (verbatim, final_capstone_project.md) Module(s) Lab(s) Repo paths Proven by Benchmark / measured metric
    LO1 Agentic architecture: bounded state-machine core; typed shared state; explicit termination and a global step/cost budget; two entry points driving the same compiled graph M1 (core), M7 (flow logic placement) lab01, lab07 src/rafeeq/core/graph.py, core/state.py, core/budget.py; flows/refund_flow.py; service/api.py (both entry points: resolve_ticket + replay_tickets) labs/lab01/solution/verify.py; tests/unit/run_without_pytest.py (state/budget tests); labs/sim/sim_no_terminate.py Loop termination on adversarial input (target: 100% halt ≤ MAX_STEPS); steps/simple task (≤3); cost/simple task (≤0.01 USD) — M1 Benchmarks table
    LO2 Reasoning patterns: the right pattern per workflow (Plan-and-Execute for refunds, ReAct for open intake, a Reflection gate on high-stakes outputs), each justified M2 lab02 src/rafeeq/reasoning/react.py, plan_execute.py, reflection.py, compare.py labs/lab02/solution/verify.py (compare_patterns); labs/sim/sim_react_thrash.py BENCHMARKS.md three-pattern cost/step comparison; redundant_tool_calls count (target: 0 for a correct ReAct loop)
    LO3 Multi-agent orchestration: a thin supervisor over Orders/Logistics/Billing specialists with scoped context, mandatory write-back, aggregation, clean escalation M5, M6 lab05, lab06 src/rafeeq/agents/specialist.py, scoping.py; orchestration/supervisor.py, delegate.py, finish.py, routing.py, agents_as_tools.py labs/lab05/solution/verify.py, labs/lab06/solution/verify.py; labs/sim/sim_lost_handoff.py; scripts/compare_arch.py (Architecture A vs B) Routing accuracy (M6 target ≥90%, capstone milestone M-B); specialist vs monolith accuracy; escalation on MAX_HANDOFFS
    LO4 MCP tool integration: Tawseel OMS/Logistics/CRM exposed as governed MCP servers with server-side authorisation; the agent consumes them via runtime discovery M3 lab03 src/rafeeq/tools/registry.py, tools/*.py; mcp_servers/{orders,logistics,billing,customer}_server.py, mcp_servers/common.py (guarded_tool) labs/lab03/solution/verify.py; tests/unit/test_tools.py (error-value contract) 16-tool catalogue, tool-selection accuracy (10/10 in verify.py); MCP discovery vs offline fallback parity
    LO5 Memory & state: thread-scoped checkpointing; customer-scoped long-term memory + versioned bilingual KB; cross-lingual retrieval; a PDPL erasure path; zero cross-customer leakage M4 lab04 src/rafeeq/memory/short_term.py, long_term.py, knowledge_base.py, vector_store.py labs/lab04/solution/verify.py; labs/sim/sim_memory_leak.py, sim_stale_policy.py; tests/security leakage tests Cross-lingual recall; leakage = 0 (hard gate, capstone M-B and rubric); forget_customer erasure to 0; KB current-vs-superseded chunk split
    LO6 Guardrails & security: input + output guardrails; structural authorisation and deterministic gates (no rule in a prompt); a red-team suite in CI with zero open high-severity findings and a triaged report M7 (gates), M8 (guardrails/red-team) lab07, lab08 src/rafeeq/flows/refund_flow.py; security/{input_guard,output_guard,action_risk,authz,red_team}.py; security/**/*.json (corpus) labs/lab07/solution/verify.py, labs/lab08/solution/verify.py; labs/sim/sim_prompt_authz.py, sim_swallowed_error.py; tests/security/run_without_pytest.py; .github/workflows/ci.yml's red_team_gate job 0 open high-severity findings (hard gate); SECURITY_REPORT.md seven-part finding shape; determinism (100/100 repeats identical)
    LO7 Observability & cost: every run traced; cost attributed by model/component/intent; caching + model routing applied; bounded retries on idempotent tools only; a BENCHMARKS.md with real measured numbers M9 lab09 src/rafeeq/observability/tracing.py, cost.py, optimise.py, retry.py, slo.py labs/lab09/solution/verify.py; labs/sim/sim_retry_write.py; evaluations/dashboard.py Cost/contact before vs after (target ≥40% cut, capstone M-D); p95 latency ≤2.5s; write-tool retries = 0 (hard gate)
    LO8 Deployment & validation: the service runs in the simulated Tawseel environment (containerised, health/readiness endpoints); an eval-harness run over tickets_eval.jsonl demonstrates task success, cost, latency, zero leakage M9 (9.5), capstone integration capstone (all labs integrated) src/rafeeq/service/api.py, health.py; Dockerfile; deployment/docker-compose.yml, deployment/runbook.md make compose-up (labs profile, healthy); python3 -m evaluations.harness --target stub; evaluations/dashboard.py Task success, cost/contact, p95 latency, leakage=0 (reports/eval_stub_baseline.{json,md}, reports/DASHBOARD.md)

    Cross-cutting: labs/sim -> module -> LO¶

    labs/sim/*.py scripts are debugging exercises, not full LO coverage on their own — each reinforces the LO of the module whose failure mode it reproduces (see labs/sim/README.md's own table for the full mapping); listed above only where directly load-bearing for that LO's proof.

    How to regenerate every number in this map¶

    export PYTHONPATH=src
make data                                             # deterministic synthetic dataset
for n in 1 2 3 4 5 6 7 8 9; do make lab$n; done        # every lab's verify.py
make bench-security                                    # LO6's security family, all columns
make redteam                                            # LO6's full red-team corpus
make eval                                               # LO8's eval harness
make dashboard                                          # LO7/LO8's DASHBOARD.md

    All of the above run fully offline (RAFEEQ_MODEL_MODE=stub) except labs 5/6 (need langgraph) — see ../README.md and OFFLINE_MODE.md.
