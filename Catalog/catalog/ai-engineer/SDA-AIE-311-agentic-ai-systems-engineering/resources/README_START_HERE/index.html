    SDA-AIE-311 — Agentic AI Systems Engineering¶

    هندسة أنظمة الذكاء الاصطناعي الوكيلي — Complete Programme Package¶

    Everything needed to deliver the five-day Expert module: the training deck, the working course repository, and the written guides. Built from INSTRUCTOR_PACKAGE.md and extended with the external research and curriculum additions agreed for this cohort.

    What is in this package¶

    Folder What it holds Who uses it
    01_Training_Deck/ 258-slide PowerPoint deck with speaker notes on every slide, plus its regenerable source Instructor
    02_Programme_Guides/ Seven written guides — handbook, delivery guide, setup, assessment, overview, visual brief, bibliography Instructor, participants, Academy, designers
    03_Course_Repository/tawseel-agentic-ai/ The Tawseel Engineering Kit — the runnable repository behind all nine labs and the capstone Participants, instructor, lab environment

    1. The training deck¶

    01_Training_Deck/SDA-AIE-311_Agentic_AI_Systems_Engineering_Deck.pptx — 258 slides, 16:9, bilingual titles, English body (per the package's convention that code and technical terms stay in English).

    • Every slide carries instructor speaker notes: what to say, what to show, what to ask, and what to cut when running late.
    • Structure: front matter (8) · Day 1 M1–M2 (47) · Day 2 M3–M4 (48) · Day 3 M5, M5.3, M6 (51) · Day 4 M7–M8 (51) · Day 5 M9, capstone, assessment, wrap-up (53).
    • All code slides quote the real files in the repository, trimmed to the teaching core — nothing is pseudocode.
    • Third-party figures (DTDC DIVA, DoorDash, OPLOG, Ryanair, DHL, Air India) are attributed on the slide as reported by their sources, never presented as our own measurements.

    deck_source/ regenerates the deck: the content is plain JSON, one file per day.

    cd deck_source
node render.js content/*.json -o ../SDA-AIE-311_Agentic_AI_Systems_Engineering_Deck.pptx

    Edit a slide by editing its JSON entry and re-rendering — no layout work, and the design stays consistent. CONTENT_SPEC.md documents every slide type. Requires Node and pptxgenjs.

    3. The course repository — the Tawseel Engineering Kit¶

    03_Course_Repository/tawseel-agentic-ai/ — 321 files, 164 Python modules, 60 documents. This is the single repository the whole week runs on: Rafeeq (رفيق), an operations agent for Tawseel (توصيل), a fictional Saudi last-mile logistics company.

    It runs offline, with no API key¶

    The most important engineering decision in the kit. A deterministic stub model, a dependency-free vector store and hashing embeddings mean every participant can develop, test and evaluate without spend or network — and the instructor's make test is deterministic. Live mode is a single environment variable, reserved for the capstone demo and red-team realism. See docs/OFFLINE_MODE.md.

    cd tawseel-agentic-ai
python3 scripts/doctor.py        # 8/8 preflight checks
make data                        # regenerate the synthetic Saudi dataset
make test-offline                # 156 assertions, no key, no network

    What is inside¶

    Area Contents
    Synthetic Saudi data 400 customers, 2,000 orders, 8,974 LaDe-shaped delivery events, 2,000 payments across five cities; bilingual policy knowledge base versioned 2026.2 with a superseded 2026.1 for the stale-policy demo
    Evaluation set 120 labelled bilingual tickets and 60 routing tickets, reused from Day 1 to Day 5
    Tools 16 governed tools across orders, logistics, billing and customer domains — narrow, typed, errors as return values, including the LaDe-derived operational set (get_delivery_events, estimate_eta, find_delivery_exception, get_driver_status)
    MCP Four servers, not one — orders, logistics, billing, customer — so trust boundaries are a design discussion, with server-side authorisation and audit
    Reasoning ReAct (including a framework-free explicit loop with a redundant-tool-call counter), Plan-and-Execute with an approval gate, bounded Reflection, and the prompt-only anti-pattern
    Memory Thread checkpointing, customer-scoped long-term memory with filter-before-rank as a PDPL control, a versioned knowledge base, and a forget_customer erasure path covering vectors and checkpoints
    Multi-agent Three specialists from one factory, structural context scoping, the monolith baseline kept alive, a thin supervisor (Architecture A) and agents-as-tools (Architecture B), plus a deterministic fast-path router
    Flows Refund and reschedule flows with rules as branches and millisecond table tests that use no model
    Security Bilingual input guard, action-risk-aware output guard, five documented defence layers, and a 78-payload attack corpus across ten AgentDojo-inspired families, roughly half in Arabic
    TawseelBench 60 scenarios in the τ-bench shape — request → policy → environment state → tools → expected state transition → pass/fail — designed to become a reusable SDAIA Academy benchmark
    Observability Local trace tree, cost attribution by model/component/intent, cache and model-routing levers with measured stats, an idempotent-only retry ledger, audit log with replay, and SLO alerts
    Labs Nine labs with start/ (TODO markers and deliberate smells) and solution/ (with a verify.py PASS/FAIL checklist), plus eight runnable failure simulations
    Capstone Brief, tickable checklist with a proving command per line, 100-point rubric, templates, instructor grading sheet and a model security report
    Deployment Docker Compose for the simulated Tawseel environment, a runbook with a brownout drill, and a CI workflow that gates on zero open high-severity red-team findings

    Verified before shipping¶

    Check Result
    scripts/doctor.py 8/8
    scripts/selfcheck.py (data referential integrity) 25/25
    tests/unit/run_without_pytest.py 92/92
    tests/security/run_without_pytest.py 39/39
    TawseelBench, 60 scenarios, reference target 100%

    Red-team suite, 78 payloads 0 open high-severity
    All nine labs/lab0*/solution/verify.py pass

    The 100% figures are the offline reference target — a deterministic implementation of what a competent agent should do, used to prove the harness itself is sound. Participants' own agents will score lower; that gap is the lesson. evaluations/KNOWN_GAPS.md records what was deliberately left open for students to close.

    What was added beyond the original instructor package¶

    1. M5.3 — "When NOT to Use Multi-Agent Systems", a full session with ten decision criteria, a decision worksheet, and Ryanair's reported consolidation from twelve agents to one as the anchor case against OPLOG as the counter-case.
    2. The Day 3 architecture challenge — teams build Architecture A (supervisor) and Architecture B (agents-as-tools) and fill a real comparison table from scripts/compare_arch.py. This turns M5/M6 into systems engineering rather than a multi-agent chat demo.
    3. TawseelBench — 60 τ-bench-shaped scenarios, positioned as an Academy asset that outlives this cohort.
    4. The attack corpus — ten families, 78 payloads, Arabic and English, with the seven-part finding shape (attack → vulnerability → exploit trajectory → business impact → detection → mitigation → retest) that makes the graded red-team report serious.
    5. Explicit ReAct before the framework — students implement the loop by hand and count unnecessary tool calls before LangGraph abstracts the control flow.
    6. Six enterprise case cards — DTDC DIVA, DoorDash, OPLOG, Ryanair, DHL Supply Chain, Air India AI.g — each with the reported facts attributed, the day it fits, and the question to put to the room.
    7. Offline-first execution, so the course is deliverable without per-participant model spend and every lab is reproducible.

    Before the first delivery — what still needs a human¶

    Four items were deliberately left for the delivery team rather than guessed at:

    1. Pin the OWASP item numbers. docs/SECURITY_MODEL.md maps controls to the OWASP Agentic Top 10 2026 categories and says so explicitly. Pin the exact published item numbers against the current list before printing the Day 4 materials.
    2. Verify the enterprise case figures at source on the delivery date. They are attributed, dated where known, and change.
    3. Commission the visual assets. VISUAL_ASSET_BRIEF.md is ready to hand to a designer; the deck currently uses built diagrams, not illustrated ones.
    4. Run the full live-mode dry run. Everything here is verified offline. A dry run with the real gateway, Qdrant, LangSmith and the four MCP servers is still required, per the instructor guide's T-minus-one-week checklist.
