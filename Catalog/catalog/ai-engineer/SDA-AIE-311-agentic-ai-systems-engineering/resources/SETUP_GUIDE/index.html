    Setup Guide¶

    SDA-AIE-311 Agentic AI Systems Engineering — participant and lab-environment setup¶

    Three tracks are offered, in order of preference. Track A (fully offline) is the default for every lab, make test, and CI — no participant needs Track B or C to complete the course. Track B is for anyone who wants the real (not stub) model, vector-store, and checkpointer stack running locally. Track C is the fallback for a machine that cannot run Docker at all.

    Repo root for every command below: tawseel-agentic-ai/. Set PYTHONPATH=src once per shell (or per command, as shown) before anything else.

    Before you start: the offline-mode promise¶

    Every lab, the full test suite, and CI run with zero API keys and zero network calls by default. Three environment variables control this, all defaulting to their offline value:

    Variable Default Meaning
    RAFEEQ_MODEL_MODE stub StubChatModel — deterministic, rule-based, bilingual, zero cost, zero network
    RAFEEQ_VECTOR_MODE simple In-memory vector store — no Qdrant/Docker required
    RAFEEQ_EMBED_MODE hashing Dependency-free embeddings — no embedding API call

    This is not a training-wheels shortcut. StubChatModel implements the same call surface a real chat model does (.invoke, .bind_tools, .with_structured_output), so code written and tested against it works unmodified against the real thing once you switch RAFEEQ_MODEL_MODE=live. Labs 1, 2, 4, 7, 8, 9 run fully offline with nothing beyond pydantic installed; Labs 5 and 6 need langgraph (still no key, no network); Lab 3's live-MCP path needs mcp + langchain-mcp-adapters (its offline tool catalogue needs neither). See docs/OFFLINE_MODE.md for the full mechanism.

    Track A — Fully Offline (the default; do this first, everyone)¶

    What you need: Python 3.11+, git. Nothing else.

    1. Clone and set the path¶

    git clone <course-org-repo-url> tawseel-agentic-ai
cd tawseel-agentic-ai
export PYTHONPATH=src

    Verify: python3 --version reports 3.11 or higher.

    2. Preflight¶

    python3 scripts/doctor.py

    Verify: the report ends 8/8 checks passed (or close to it — a missing optional Layer-B package is expected and listed by name, not a failure) and states which labs run fully offline right now (1, 2, 4, 7, 8, 9) versus which need one more pip install (5, 6 need langgraph; 3's live-MCP path needs mcp + langchain-mcp-adapters).

    3. Generate the deterministic dataset¶

    make data

    This runs data/generate.py (seeded by RAFEEQ_SEED=20260311, so every participant's data is byte-identical) followed by scripts/selfcheck.py (referential-integrity check).

    Verify: no errors printed; data/orders/orders_seed.json (2,000 orders), data/customers/customers_seed.json (400 customers), data/tickets_eval.jsonl (120 labelled bilingual tickets), and data/routing_eval.jsonl (60 labelled tickets) now exist.

    python3 -c "import json; print(len(json.load(open('data/orders/orders_seed.json'))))"
# -> 2000

    4. Run the full offline test suite¶

    make test-offline

    This runs tests/unit/run_without_pytest.py and tests/security/run_without_pytest.py — stdlib test runners requiring no pytest install.

    Verify: ends 88/88 checks passed (unit) and 39/39 checks passed (security). If pytest happens to be installed, make test runs the same checks via pytest instead and produces the same pass counts.

    5. Try a lab¶

    make lab1
# or directly:
python3 labs/lab01/solution/verify.py

    Verify: ends 10/10 checks passed. Every lab from 1–9 follows the same pattern — make labN or python3 labs/labNN/solution/verify.py — and every verify.py prints its own numbered PASS/FAIL checklist, so "did it work" is never a judgement call.

    Track A is sufficient for the entire course. Tracks B and C below are optional, for participants who want the real model/vector-store/checkpointer stack (recommended before the capstone demo) or whose machine cannot run Python locally at all.

    Track B — Local, Full Stack (Docker + Qdrant + gateway key)¶

    Use this once you are comfortable with Track A and want to run Labs 5/6 against a real LangGraph build, exercise RAFEEQ_VECTOR_MODE=qdrant, or rehearse the capstone demo in live mode.

    1. Docker¶

    Install Docker Desktop (Windows: enable WSL2 integration; see the troubleshooting appendix) or Colima on macOS/Linux.

    Verify: 

    docker run hello-world
    Prints "Hello from Docker!".

    2. Install the full Python dependency set¶

    pip install -r requirements.txt -r requirements-dev.txt

    This adds, on top of Track A's pydantic: fastapi, uvicorn, langgraph, langchain-core, langchain-openai, langsmith, mcp, qdrant-client, psycopg[binary], langgraph-checkpoint-postgres, and (dev-only) pytest, ruff.

    Verify: 

    python3 scripts/doctor.py
    The optional-dependency survey should now show most or all of the nine Layer-B packages present, and the verdict section should no longer flag Labs 5/6/3-live as needing an install.

    3. Bring up the full compose profile¶

    docker compose -f deployment/docker-compose.yml --profile full up -d
docker compose -f deployment/docker-compose.yml --profile full ps

    This starts Qdrant (long-term memory + versioned KB), Postgres (the LangGraph checkpointer — short-term/thread-scoped memory), the four MCP servers (orders, logistics, billing, customer), and sim-backends (the mock Tawseel OMS/logistics/CRM/billing backends), wired with ordered health-check dependencies — rafeeq-api will not accept traffic until every dependency reports healthy.

    Verify: every row in the ps output shows healthy, not just running.

    curl -s http://localhost:8000/readyz | python3 -m json.tool
    Reports "status": "ok" with per-check detail (seed data present, vector store constructs, all four MCP servers import, active RAFEEQ_MODEL_MODE).

    4. Configure the gateway key (live mode only)¶

    cp .env.example .env
    Edit .env and set: 
    RAFEEQ_MODEL_MODE=live
OPENAI_API_KEY=<the course gateway key>
OPENAI_BASE_URL=<course gateway URL, if not api.openai.com>

    Verify: 

    export RAFEEQ_MODEL_MODE=live
python3 scripts/doctor.py
    The "model gateway reachable" check now actually makes a network call (only happens when RAFEEQ_MODEL_MODE=live) and should report [PASS]. Do not leave RAFEEQ_MODEL_MODE=live set for routine lab work — switch back to stub (or simply unset RAFEEQ_MODEL_MODE) so you are not spending gateway budget on iteration; reserve live mode for the capstone demo and the PA-2 live retest (docs/OFFLINE_MODE.md's "when a participant MUST switch to live mode" section).

    5. Smoke-test the running service¶

    curl -s -X POST http://localhost:8000/v1/resolve \
  -H 'Content-Type: application/json' \
  -d '{"ticket_id":"TKT-SMOKE-1","text":"أين طلبي رقم TW-2026-88120؟","locale":"ar","customer_id":"CUST-4471","order_id":"TW-2026-88120"}'

    Verify: a JSON response resolving the ticket, correctly in Arabic.

    Tear-down¶

    docker compose -f deployment/docker-compose.yml --profile full down

    Track C — Cloud Fallback (Codespaces-style)¶

    For a machine that cannot run Docker or a recent Python locally (locked-down corporate laptop, insufficient disk/RAM).

    1. Open the course repository in a cloud dev-container environment (GitHub Codespaces or your Academy's equivalent) using the repo's own container definition — the same python:3.11-slim base the Dockerfile uses, so behaviour matches every other track.
    2. In the cloud terminal, run Track A steps 1–5 verbatim (export PYTHONPATH=src, python3 scripts/doctor.py, make data, make test-offline, make lab1). Nothing about the offline track changes in a cloud container.
    3. If the cloud environment offers a pre-provisioned Docker-in-Docker or a hosted Qdrant, Track B's steps also transfer unchanged — only the docker compose host differs, not the commands.
    4. Verify exactly as in Track A/B: the same doctor.py verdict, the same 88/88/39/39 test counts, the same /readyz response.

    Cloud fallback participants should still complete Track A locally-in-the-cloud first (zero dependencies, fastest to a working state) before attempting Track B's full stack in the same environment.

    Troubleshooting Appendix¶

    Windows / WSL2¶

    Symptom Cause Fix
    docker run hello-world fails with a WSL-integration error Docker Desktop's WSL2 backend not enabled for your distro Docker Desktop → Settings → Resources → WSL Integration → enable your distro; restart Docker Desktop
    python3: command not found in WSL Some WSL Ubuntu images ship python3 but not the python alias, or no Python at all sudo apt update && sudo apt install python3.11 python3-pip; always invoke python3, never python, per every command in this guide
    Paths with C:\Users\... fail inside WSL commands Running commands from a Windows shell against a WSL-cloned repo (or vice versa) Clone the repository inside the WSL filesystem (~/tawseel-agentic-ai, not /mnt/c/...) and run every command from the WSL terminal — cross-filesystem access is slow and occasionally breaks file-lock behaviour Docker needs
    docker compose hangs on full profile bring-up WSL2 memory limit too low for Qdrant + Postgres + 4 MCP servers + API Increase the WSL2 memory cap in %UserProfile%\.wslconfig (memory=8GB or higher), then wsl --shutdown and restart Docker Desktop

    Corporate proxy¶

    Symptom Cause Fix
    pip install in Track B times out or fails TLS verification Corporate proxy intercepting HTTPS without a trusted CA, or pip not proxy-aware Set HTTP_PROXY/HTTPS_PROXY env vars per your IT policy; if TLS is intercepted, install your organisation's CA bundle and point pip at it (PIP_CERT=/path/to/corp-ca-bundle.crt) — never pass --trusted-host as a substitute for a real CA unless your security team explicitly signs off
    docker pull fails for qdrant/qdrant or postgres images Proxy blocks Docker Hub or requires an authenticated registry mirror Configure Docker Desktop's proxy settings (Settings → Resources → Proxies), or ask your Academy IT contact for a pre-mirrored internal registry per instructor_guide.md's "confirm the classroom network allows... package index" checklist item
    RAFEEQ_MODEL_MODE=live gateway check fails even with a valid key Proxy blocking the gateway's outbound host Confirm the gateway hostname is on the classroom network's allowlist (an instructor pre-session task); Track A/B's offline steps are entirely unaffected — you do not need the gateway for any lab

    Arabic font / console issues¶

    Symptom Cause Fix
    Arabic text in terminal output shows as boxes (□□□) or reversed/garbled Terminal font lacks Arabic glyphs, or the terminal does not apply bidirectional (BiDi) text shaping Windows Terminal, iTerm2, and GNOME Terminal all handle Arabic BiDi correctly out of the box — if using a legacy console (cmd.exe), switch to Windows Terminal; ensure the font is a Unicode-complete family (Cascadia Code, Noto Sans Arabic, or any modern default)
    Arabic renders correctly in the terminal but garbled in a redirected file (> out.txt) File written/read with the wrong encoding Always open/redirect as UTF-8 explicitly: python3 script.py > out.txt is fine on any modern OS, but if editing on Windows, open the file in an editor that defaults to UTF-8 (VS Code does), not Notepad's legacy ANSI mode
    pytest/verify.py output with Arabic ticket text looks fine, but a copy-pasted Arabic ticket into a terminal prompt behaves oddly (character order visually reversed) Expected BiDi rendering behaviour in some terminals for mixed Arabic/Latin/digit strings (e.g. TW-2026-88120 inside an Arabic sentence) — this is a display artefact only Verify correctness by checking the underlying bytes/JSON (data/tickets_eval.jsonl), not the terminal's visual rendering; this is exactly the tokenisation/rendering awareness Module 4 asks participants to notice, not a setup defect to "fix"
    make data/scripts/selfcheck.py reports a policy or ticket file encoding error A local editor re-saved a bilingual data/policy file in a non-UTF-8 encoding Re-generate from source (make data regenerates everything deterministically) rather than hand-editing generated files; if editing data/policies/ar/*.md by hand, save explicitly as UTF-8 (no BOM)

    General¶

    Symptom Cause Fix
    ModuleNotFoundError: No module named 'rafeeq' PYTHONPATH=src not set for this shell/command export PYTHONPATH=src once per shell, or prefix each command: PYTHONPATH=src python3 ...
    make data / make test-offline "works" the first run but a later run reports different-looking output Nothing is actually non-deterministic — RAFEEQ_SEED=20260311 is fixed — but stale __pycache__ or a partially-written data file from an interrupted previous run can look like drift make clean then make data again
    A lab's verify.py fails with an ImportError naming a pip install line You are running a Layer-B lab (5, 6, or 3's live-MCP path) without that package installed — this is by design (SPEC's import-guard rule), not a bug Either pip install the named package (Track B), or stay on the Layer-A subset of that lab if your instructor has scoped it down
    Docker healthcheck never turns healthy on the full profile A dependent service (Qdrant/Postgres) itself unhealthy, often first-boot volume initialisation taking longer than the healthcheck's start_period docker compose -f deployment/docker-compose.yml --profile full logs <service> to see the actual failure; re-run ps after a minute — first boot is often slower than the steady state
