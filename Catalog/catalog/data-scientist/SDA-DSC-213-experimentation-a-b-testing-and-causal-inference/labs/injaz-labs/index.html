    SDA-DSC-213 — Experimentation, A/B Testing and Causal Inference¶

    التجريب واختبارات A/B والاستدلال السببي¶

    SDAIA Academy · Data Scientist track · Specialist level · 4 days × 5 learning hours = 20 hours

    This repository is the complete delivery package for SDA-DSC-213: 17 notebooks (eight start/solution pairs — Lab 5 is split into 5a and 5b — plus a capstone starter), 12 synthetic datasets with planted ground truths, a reusable causal_utils toolkit, 30 figures, and the instructor and participant documents.

    Field Value
    Course code SDA-DSC-213
    Prerequisite SDA-DSC-111
    Audience Working data scientists supporting product, policy and programme decisions in Saudi government and enterprise
    Delivery language English or Arabic — all code, identifiers and variable names stay in English
    Assessment Experiment design and analysis project (the capstone)
    Next in the path SDA-DSC-311 Decision Science and Optimization Modeling
    Data 100% synthetic, generated by data/make_data.py. No real citizen or government data is used anywhere.

    1. The Injaz golden thread¶

    Every module, lab and dataset in this course is about the same fictional platform: Injaz (إنجاز), a unified Saudi digital-government services platform where citizens renew licences, issue certificates, update addresses and pay fees online.

    There are no throwaway examples. Participants carry one analysis notebook from Hour 1 to the capstone, and each lab adds a component to one toolkit. Four questions run through the four days:

    Thread The decision Method Where
    Guided uploader Does a redesigned document-upload step raise service completion? randomised A/B test Days 1–2
    Regional reminders Did the region-by-region reminder rollout raise completion? difference-in-differences Day 3
    Digital-literacy training Did the voluntary training programme help those who took it? matching / IPW Day 3
    AI autofill Should we launch autofill nationally? capstone A/B + causal evaluation Day 4

    Two design rules make the thread work, and both are non-negotiable in delivery:

    1. Simulation first. Every method is taught on a simulator where the true effect was planted, then applied to Injaz data where the truth is unknown. Participants only trust a method after they watch it recover a number somebody deliberately put there. data/GROUND_TRUTH.json is that list of planted numbers.
    2. An honest "we cannot conclude" is a full-marks answer. The capstone data is built so that the correct verdict on the autofill launch is hold and extend, not ship. This is stated on Day 1 and graded on Day 4.

    3. Five-minute quickstart¶

    # 1. Get a clean environment (any venv/conda tool is fine)
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate

# 2. Install. Start with the core stack - it is all any lab strictly needs.
pip install -r requirements-core.txt

#    Optional, and heavier: the DoWhy/EconML convenience layer.
pip install -r requirements.txt

# 3. Generate the datasets (fixed seeds - everyone gets identical numbers)
cd data && python make_data.py && cd ..

# 4. Verify. This must print PASS and exit 0.
python environment_check.py

# 5. Open Lab 1
jupyter lab notebooks/lab1_start.ipynb

    environment_check.py checks the Python version, imports every required package, lists which optional ones are missing (and says so is fine), confirms all 12 datasets exist with the right row counts, and runs three fast assertions against the planted truths. A clean run ends with:

    RESULT: PASS — environment is ready to teach
  required packages : all importable
  datasets          : 12 files, all present with the expected row counts
  ground truth      : 3/3 smoke assertions passed

    4. Environment strategy¶

    Primary: local Jupyter (or VS Code + Python extension) on Python 3.12. Python 3.10 and 3.11 also work; environment_check.py enforces ≥ 3.10.

    The core stack — required. numpy, pandas, scipy, statsmodels, matplotlib, scikit-learn, pyarrow, plus a notebook UI.

    The causal stack — optional. dowhy, econml, linearmodels, networkx. These have by far the heaviest dependency chain and are the single most common cause of a lost first hour.

    Every lab in this course runs on the core stack alone.

    DoWhy appears only in Labs 5a, 5b and 6, and every such cell is marked OPTIONAL: DoWhy equivalent (safe to run; skips if not installed) — it is guarded, so it degrades to a printed note rather than an error. The causal_utils equivalent sits immediately beside it and produces the same estimate with statsmodels. EconML and linearmodels are not used by any notebook at all; they exist only for the optional capstone extensions:

    Optional call Core-stack fallback in causal_utils
    dowhy identify → estimate → refute InjazDAG(...).minimal_adjustment_set() → regression_effect(...) → placebo_outcome_test / random_common_cause_test / subset_refutation
    dowhy backdoor identification backdoor_adjustment_sets(graph, treatment, outcome)
    econml causal forest (CATE) — capstone extension only pre-registered subgroup regression_effect + correct_pvalues(method="bh")
    linearmodels panel IV / IV2SLS — capstone extension only iv_2sls(...) (first-stage F reported, HC3 SEs)
    networkx DAG drawing the printed adjustment set and backdoor-path list from InjazDAG.explain()

    A participant who cannot install DoWhy is inconvenienced, not blocked. Say this out loud on Day 1 so nobody spends Lab 6 fighting pip.

    Fallback: Google Colab. Every notebook's first cell is a commented !pip install block. Uncomment it, run once, and upload the data/ folder (or run make_data.py in Colab). See instructor/SETUP_GUIDE.md for the full Colab path, including what to do when a participant's machine can install nothing at all.

    Restricted networks. If the classroom cannot reach PyPI, pre-mirror wheels for the causal stack, or simply teach on requirements-core.txt — see the fallback table above.

    5. Regenerating the data¶

    All 12 datasets come from one script with fixed seeds. Regenerating on any machine reproduces the same numbers to the last digit.

    cd data
python make_data.py

    This rewrites every .csv, .csv.gz and .parquet file in data/ and GROUND_TRUTH.json, which records the planted effects actually realised in the generated sample (e.g. the uploader lift is planted at +2.2 pp and realises at +2.1631 pp).

    After regenerating, always run python environment_check.py. If a smoke test fails, the seeds moved and instructor/ANSWER_KEY.md no longer matches what participants will see — regenerate the answer-key numbers before teaching.

    Do not regenerate mid-cohort. Participants who generated data on Day 1 and again on Day 3 will get different numbers from their neighbours, and the shared leaderboard stops working.

    7. What gets assessed¶

    Component Weight Evidence
    Lab completion (7 labs) 30% checkpoint notebooks + expected outputs
    PA-1 (Day 2) + PA-2 (Day 3) 20% corrected analyses + written diagnoses
    Quiz (10 of the 20 questions, 15 min, closed book) 10% instructor/QUIZ_BANK.md
    Capstone 40% frozen plan, analysis, memo — reasoning first

    Pass ≥ 70. Distinction ≥ 90. The Causal badge requires ≥ 70 overall and capstone ≥ 70 and zero academic-integrity flags. A correct, well-justified null or non-identifiability verdict never counts against a participant.

    8. Vocabulary used consistently throughout¶

    Term Meaning as used here
    OEC Overall Evaluation Criterion — the single primary decision metric. Exactly one per experiment.
    Guardrail A metric that must not get worse, tested as a family with FWER control.
    Trigger Whether a unit actually reached the changed step. The analysis population is triggered users, not all assigned users.
    Estimand The causal quantity you are after (ATE / ATT / LATE / CATE), named before touching data.
    Frozen plan The design doc + analysis plan, hashed and committed before results exist. causal_utils.freeze_plan() stamps and hashes it.
    Practical threshold The effect size below which the result does not justify acting. Distinct from statistical significance.

    All code targets Python 3.10+ (3.12 recommended). Every causal method is taught simulation-first on the Injaz golden thread: plant a known effect, recover it, then apply it where the truth is unknown.
