    Setup Guide¶

    SDA-DSC-213 · Experimentation, A/B Testing and Causal Inference · SDAIA Academy Instructor document. Work through this in order. Nothing here takes long; everything here costs an hour of classroom time if it is skipped.

    Naming note. The catalogue text refers to a script called check_env.py. In this package the script is environment_check.py, at the root of course_assets/. Use that name in every message you send participants.

    1. T-minus 1 week — instructor checklist¶

    Allow 90 minutes. Do it on a clean machine or a fresh virtual environment, not on the laptop where everything already works.

    • Clone / copy the course package and confirm the tree matches §2 of README.md: data/, causal_utils/, notebooks/ (17 notebooks), figures/ (30 PNGs), capstone/, instructor/.
    • Create a clean environment and install the core stack: pip install -r requirements-core.txt.
    • Regenerate the datasets from fixed seeds: cd data && python make_data.py && cd ... This rewrites all 12 data files and GROUND_TRUTH.json.
    • Run python environment_check.py. It must print RESULT: PASS and exit 0. If any of the three ground-truth smoke tests fails, the seeds have moved and ANSWER_KEY.md no longer matches what participants will see — regenerate the answer-key numbers before teaching.
    • Install the optional causal stack in a second environment: pip install -r requirements.txt (adds dowhy, econml, linearmodels, networkx). This is the heaviest dependency chain in the course; test it early, and test it on the Colab fallback too.
    • Dry-run all 7 labs end to end, *_start.ipynb then *_solution.ipynb. Time Labs 4 and 5b specifically — they are the two overrun-prone sessions and you need to know your own pace on them.
    • Confirm the no-DoWhy path. Deliberately run Lab 6 and the capstone starter in the core-only environment and confirm every optional cell is skippable with a causal_utils equivalent immediately below it. You will have at least one participant who cannot install DoWhy.
    • Verify the classroom can reach PyPI. If it cannot, pre-mirror wheels for the causal stack, or plan to teach entirely on the core stack (which is fully supported — see §7).
    • Print the A4 posters: two-worlds counterfactual (m1_two_worlds.png), MDE-vs-n quadratic (m3_mde_vs_n.png), the three DAG junctions (m6_three_junctions.png), the method-selection flowchart (m7_method_selection.png). The MDE curve stays on the wall from Day 2 Hour 1 to the end.
    • Load the simulators and check the sliders work: confounding dial, peeking sandbox, collider generator, parallel-trends breaker.
    • Set up the shared leaderboard (recovered ATE accuracy, sizing plans, DiD estimates). One shared sheet is enough.
    • Print RUN_OF_SHOW.md, ANSWER_KEY.md and QUIZ_BANK.md double-sided. You will not want to be scrolling on Day 4.
    • Prepare PA-1 and PA-2 handouts and decide when PA-2 runs (see the deviation note in RUN_OF_SHOW.md, Day 3 Hour 5).
    • Send the participant setup email (§3) — a full week out, so there is time for a second round with anyone who is stuck.

    2. T-minus 2 days — checklist¶

    Allow 45 minutes.

    • Chase every participant who has not replied to the setup email with their environment_check.py output. Assume silence means "not done". This single follow-up is worth more than any other item on this list.
    • Triage the failures. Sort replies into: (a) PASS — nothing to do; (b) core-stack failure — fix over email using §6; (c) optional-stack failure only — reassure them, it is fine; (d) cannot install anything — put them on the Colab path (§7) and confirm they have run the install cell once before Day 1.
    • Prepare 2–3 loaner machines or a shared Colab workspace for the people who will nevertheless arrive broken. There is always at least one.
    • Confirm the classroom has: reliable Wi-Fi, a projector that renders matplotlib legibly from the back row, a whiteboard large enough for the Day 1 derivation, and power at every seat.
    • Confirm room bookings against the prayer schedule for the actual teaching dates, and adjust the whole grid in RUN_OF_SHOW.md if Dhuhr has moved. Do not adjust individual hours.
    • Copy the datasets to a USB drive and to a shared folder. A participant who cannot run make_data.py should be able to copy data/ in 30 seconds.
    • Rerun environment_check.py on the teaching machine — the one you will actually project from.
    • Decide the briefing format for Day 4 Hour 5 (six-minute briefings, or three-minute board briefings for a large cohort). Decide it now, not at 13:55 on Day 4.

    3. Participant setup email — ready to send¶

    Send at T-minus 1 week. Copy from the line below; replace the four bracketed fields.

    Subject: SDA-DSC-213 — please set up your laptop before [DATE] (about 20 minutes)

    Dear participant,

    Welcome to Experimentation, A/B Testing and Causal Inference (SDA-DSC-213), running [DATES] at [LOCATION].

    This is a hands-on course: you will be writing and running code from the third hour of Day 1. Please complete the setup below before the course starts and reply to this email with the output of the final step. It takes about twenty minutes, and doing it now means we spend Day 1 on causal inference rather than on pip.

    1. Install Python 3.12 (3.10 or 3.11 also work) from python.org, or use an existing Anaconda/Miniconda installation.

    2. Create a clean environment and install the core packages.

    python -m venv sda-dsc-213
source sda-dsc-213/bin/activate        # Windows: sda-dsc-213\Scripts\activate
pip install numpy scipy pandas matplotlib statsmodels scikit-learn pyarrow jupyterlab

    3. Install the optional causal packages. These have the heaviest dependency chain in the course, which is why we ask you to try them early:

    pip install dowhy econml linearmodels networkx

    If this step fails, do not worry and do not spend time on it. Every lab in the course runs without these packages — each notebook provides an equivalent that uses only the packages from step 2. Just tell us in your reply that step 3 did not work.

    4. Download the course package from [LINK] and unzip it.

    5. Generate the datasets.

    cd course_assets/data
python make_data.py
cd ..

    6. Verify everything, and send us the result.

    python environment_check.py

    You should see RESULT: PASS at the end. Please reply to this email with the last ten lines of that output, whether it passed or failed. If it failed, send it anyway — that is exactly what we need to help you before Day 1.

    If you cannot install software on your machine (a locked-down work laptop, for example), reply and say so. We will send you a Google Colab link that runs everything in the browser with no installation at all.

    Before Day 1, please also refresh hypothesis testing and confidence intervals from SDA-DSC-111 — the linked pre-read takes about 30 minutes.

    On the day, please bring: your laptop and charger, and the machine you actually did the setup on.

    We look forward to seeing you.

    [INSTRUCTOR NAME] SDAIA Academy

    4. How to verify an environment¶

    Ask for the output of one command; everything else is guesswork.

    python environment_check.py

    A passing run ends with:

    RESULT: PASS — environment is ready to teach
  required packages : all importable
  datasets          : 12 files, all present with the expected row counts
  ground truth      : 3/3 smoke assertions passed

    How to read the sections:

    Section What a problem there means
    1. Python Below 3.10 — reinstall. This is the only version problem worth fixing.
    2. Required packages A blocking failure. The named pip install line in the message is the fix.
    3. Optional packages Never blocking. skip lines here are expected and fine.
    4. Course toolkit causal_utils is not importable — they are running the script from the wrong directory, or the package did not unzip fully.
    5. Datasets Missing or wrong row counts — cd data && python make_data.py.
    6. Supporting files An incomplete copy of the package. Re-download.
    7. Ground-truth smoke tests The data exists but the planted truths have drifted — the seeds moved. Regenerate; if it persists, the answer key needs regenerating too.

    Useful flags: --quiet prints summary lines only; --root /path/to/course_assets runs it against a package elsewhere on disk. The script exits non-zero on failure, so it can be dropped into a CI check.

    5. Colab fallback — the standing plan B¶

    Every notebook's first cell is a commented install block. The Colab path is:

    1. Open the notebook in Colab (File → Upload notebook, or from Drive).
    2. Uncomment and run the first cell: 
      !pip install -q numpy scipy pandas matplotlib statsmodels scikit-learn pyarrow
!pip install -q dowhy econml linearmodels networkx   # optional, slow
    3. Get the data into the session — either upload the data/ folder, or run make_data.py in Colab, or mount Google Drive with a shared copy of data/. For a whole class, the Drive-mount route is fastest.
    4. Upload causal_utils/ alongside the notebook, or sys.path.append the folder from Drive.
    5. Run environment_check.py --root <path> in a cell to confirm.

    Cost: roughly five minutes per session for the optional packages, and the runtime resets if the tab is idle. Tell Colab users to re-run the install cell after any disconnect, and to download their notebook at every break — a lost runtime on Day 4 costs their capstone.

    6. The eight issues you will actually see¶

    Ordered by how often they occur.

    1. DoWhy / EconML installation fails — frequency: high¶

    Symptom. Long dependency resolution, a compiler error, or a version conflict with an existing numpy/scikit-learn.

    Fix. In order: (a) do nothing — say clearly that the course runs without them and point at the fallback table in README.md §4; (b) install into a clean virtual environment rather than the system Python; (c) pin versions from requirements.txt; (d) use Colab for Lab 6 and the capstone extension only; (e) in a restricted network, install from pre-mirrored wheels.

    Say this to the room on Day 1: "If DoWhy will not install, you are inconvenienced, not blocked. Every lab has a path that needs only numpy, pandas, scipy, statsmodels and scikit-learn."

    2. "No module named causal_utils" — frequency: high¶

    Symptom. The import fails in a notebook that ran fine yesterday.

    Fix. They opened the notebook from a different working directory. Either launch Jupyter from the course_assets/ root, or add at the top of the notebook:

    import sys, pathlib
sys.path.append(str(pathlib.Path.cwd().parent))   # from notebooks/ -> course_assets/

    3. A dataset is missing or has the wrong row count — frequency: high¶

    Symptom. FileNotFoundError, or environment_check.py reports a row-count mismatch.

    Fix. cd data && python make_data.py. If the counts still differ, they have an older copy of make_data.py — re-copy the package. Never regenerate data mid-cohort: participants who regenerate on Day 3 get numbers that no longer match their neighbours' or the leaderboard's.

    4. pyarrow missing, so the .parquet files will not load — frequency: medium¶

    Symptom. Lab 1 or Lab 6 fails on pd.read_parquet with an engine error.

    Fix. pip install pyarrow. It is in the core requirements but is the one package people drop when they hand-type the install line. environment_check.py catches it in section 2.

    5. The notebook kernel is not the environment they installed into — frequency: medium¶

    Symptom. Packages install successfully but the notebook still cannot import them.

    Fix.

    python -m ipykernel install --user --name sda-dsc-213

    then select that kernel in the notebook. Confirm with import sys; print(sys.executable) in a cell and compare it to the interpreter: line printed by environment_check.py.

    6. Plots do not render, or render illegibly — frequency: medium¶

    Symptom. Blank output cells, or text too small to read from the back row.

    Fix. %matplotlib inline at the top of the notebook. For legibility, call causal_utils.use_sdaia_style(base_size=13) when projecting — it matches the deck and enlarges the base font.

    7. Results differ between participants — frequency: medium¶

    Symptom. Two people get different ATE estimates from the same lab.

    Fix. Three causes, in order of likelihood: (a) the seed was not set, or was set after the first random draw; (b) they regenerated the data at different times with a modified make_data.py; (c) they are analysing different rows — usually all assigned users versus triggered users, which is the Day 2 trap and worth surfacing to the whole room rather than fixing quietly.

    8. The machine cannot install anything at all — frequency: low, but always at least one¶

    Symptom. A locked-down corporate laptop: no admin rights, a blocked package index, or a proxy that intercepts TLS.

    Fix. Go to Colab (§5) immediately. Do not spend Day 1 fighting the proxy. Give them the Drive-mounted data/ and causal_utils/ folders so they skip the upload step, and pair them with someone on a working local install so that at least one machine in the pair can run everything. Remind them to download their notebook at every break.

    7. If a participant cannot install anything — the full Colab path¶

    Prepare this before Day 1, once, and reuse it for every cohort.

    1. Put data/ and causal_utils/ in a shared Google Drive folder with view access for the cohort.
    2. Prepare a header cell that participants paste into any lab notebook:

    from google.colab import drive
drive.mount('/content/drive')
import sys
sys.path.append('/content/drive/MyDrive/SDA-DSC-213/course_assets')
DATA = '/content/drive/MyDrive/SDA-DSC-213/course_assets/data/'
import causal_utils as cu
    3. Have them change the data paths in each notebook from ../data/ to DATA. One find-and-replace per notebook. 4. Optional packages: !pip install -q dowhy econml linearmodels networkx, run once per session, roughly five minutes. If time is short, skip it — the core-stack path is fully supported. 5. Verify with !python /content/drive/MyDrive/SDA-DSC-213/course_assets/environment_check.py --root /content/drive/MyDrive/SDA-DSC-213/course_assets.

    What this costs them. Nothing on Days 1–3. On Day 4, the risk is a runtime disconnect during the capstone build. Mitigate it: tell Colab users at every break to File → Download → Download .ipynb, and check they have done it at the M-B and M-C gates.

    8. Post-course¶

    • Collect: analysis notebooks, frozen design docs, decision memos, self-audit checklists, quiz papers, PA-1 and PA-2 scripts.
    • Score the capstone against the rubric in capstone/CAPSTONE_BRIEF.md §6. Grade the reasoning and honesty first, the point estimate second.
    • Check for academic-integrity flags: identical simulated seeds and identical results across submissions.
    • Issue Causal-badge recommendations within 5 working days. The badge requires ≥ 70 overall, capstone ≥ 70, and zero integrity flags.
    • Record which segments overran and by how much; annotate your copy of RUN_OF_SHOW.md for the next cohort. Labs 4 and 5b are the ones worth timing precisely.
