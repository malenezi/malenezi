    Data Dictionary — SDA-DSC-111 · Statistical Foundations for Data Science¶

    Mawid Analytics course data pack · SDAIA Academy

    All data is synthetic, generated by generate_data.py (course seed 42, pinned numpy/scipy/pandas versions in environment.yml). It is modelled on a national primary-care clinic-booking platform. No real patient data is used anywhere.

    1. clinic_visits.csv — the golden thread (50,000 rows × 15 columns)¶

    Used in every module (M1–M7) and the capstone. One row = one booked appointment.

    Column Type Description
    appointment_id str Unique appointment identifier (AP000001…)
    region str One of the 13 administrative regions of Saudi Arabia (English name; Arabic names in region_reference.csv)
    clinic_id str Clinic identifier (CL001–CL120); the clustering key for the Module-7 cluster bootstrap
    clinic_type str urban / rural — a stratification key for Module 5
    risk_band str Baseline segment risk quartile Q1(low)–Q4(high), built from clinic type, region, and clinic history. This is the Module-5 confounder: it drove the reminder rollout and it drives no-shows
    patient_age int Patient age in years (15–90)
    lead_time_days int Days between booking and appointment (0–60)
    prior_no_shows int Patient's no-shows in the previous 12 months (0–6)
    sms_reminder 0/1 Patient received an SMS reminder. Observational for ab_pilot == 0 rows (targeted at high-risk segments); randomized 50/50 for ab_pilot == 1 rows
    ab_pilot 0/1 Row belongs to the 8,000-appointment randomized reminder pilot (Module 4's clean A/B test). The pilot ran in higher-risk segments, where the Ministry piloted first
    rescheduled 0/1 Patient proactively rebooked after contact — a mediator on the reminder→no-show path (Module 5: do not adjust for it)
    staff_on_shift int Clinical staff on shift at the appointment time (2–12)
    is_peak_hour 0/1 Appointment in a peak-demand hour
    wait_time_min float Minutes waited by attended patients; NaN for no-shows (they never waited). Right-skewed — lognormal, not Normal
    no_show 0/1 Patient did not attend (the golden-thread outcome)

    Reference values in the shipped file (seed 42) — instructors verify these before delivery:

    Quantity Value
    Overall no-show rate 0.183 · Wilson 95% CI [0.179, 0.186]
    Wait time (attended) median 18 min (IQR 12–26) · mean 20.5 · SD 11.6 · skew +1.7
    Crude reminder comparison (confounded!) reminded 0.195 vs not reminded 0.175 — reminders look harmful
    Stratified by clinic_type urban 0.124 vs 0.162 · rural 0.257 vs 0.303 — reminders help in both
    Stratified by risk_band reminders help in all four bands (−4 to −5 pp)
    Reminder allocation (observational rows) ~78% of rural vs ~25% of urban patients reminded — the confounding mechanism
    Direct-standardised adjusted difference −5.0 pp (reminders reduce no-shows)
    Adjusted logistic odds ratio (sms_reminder) 0.71 [0.67, 0.75] (with lead time, priors, risk band, age held fixed)
    Randomized pilot (ab_pilot==1, n=8,000) control 0.223 vs reminder 0.155 · diff −6.8 pp · z=−7.7 · one-sided p≈5e-15 · OR 0.64
    Regions excluding the national rate Makkah (0.208, high) and Eastern Province (0.156, low) — 2 of 13. The smallest region (Al-Jouf, n≈414) shows 0.157 [0.125, 0.195] → overlaps national; do not act on it

    Design note for instructors. The instructor package describes the SMS analysis in two ways (a clean A/B test in Module 4; a confounded crude comparison in Module 5). The data reconciles them explicitly: the randomized pilot (ab_pilot == 1) is Module 4's clean test; the observational rollout (targeted at high-risk segments) is what makes the crude full-data comparison reverse in Module 5. Adjusting for risk_band (M5) or fitting the logistic model (M6) recovers the pilot's protective effect — the same truth from three methods.

    2. ab_daily_log.csv (21 rows)¶

    Day-by-day accrual of the randomized pilot, for Module 4's peeking simulation. Columns: trial_day (1–21), n_control, noshows_control, n_reminder, noshows_reminder.

    3. survey_responses.csv (48,000 rows)¶

    Module 2 case study ("The satisfaction score that lied"). Columns: survey_id, region, channel, satisfaction (1–5). channel = sms_optin (47,500 rows, ~9% response rate, satisfied patients over-respond → mean 4.59); channel = callback_nonresponder (500 stratified callbacks of non-responders → mean 3.0). Non-response bias in one file: the big-n dashboard number is precisely wrong.

    4. clinic_reference.csv (120 rows)¶

    clinic_id, region, clinic_type, avg_daily_slots, n_appointments, baseline_noshow_rate — stratification keys and Module-1 per-clinic overbooking work.

    5. region_reference.csv (13 rows)¶

    region, region_ar (Arabic name), volume_share, n_rows_in_dataset, n_clinics — for per-region planning in Module 3.

    6. small_pilot.csv (25 rows)¶

    A tiny rural-clinic extract (appointment_id, clinic_id, sms_reminder, wait_time_min, no_show) for demonstrating resampling's small-sample limits in Module 7.

    7. generate_data.py¶

    The course generator. Regenerate everything with python generate_data.py (seed 42) against the pinned versions in environment.yml, and verify the reference values above before each delivery. Passing a different seed (python generate_data.py 7) produces an alternative cohort dataset — useful for producing per-cohort variants so copied capstone analyses are detectable by their bootstrap digits.

    SDAIA Academy — internal use only. Do not distribute.
