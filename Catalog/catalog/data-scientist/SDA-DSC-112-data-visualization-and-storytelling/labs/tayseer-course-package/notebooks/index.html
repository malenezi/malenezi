    Hands-on lab notebooks — SDA-DSC-112¶

    Data Visualization and Storytelling · SDAIA Academy · Data Scientist Track

    Twelve notebooks: a starter and a solution for each of the six hands-on labs. Every lab runs against the same golden thread — the Tayseer (تيسير) National Digital Services Programme — so the story compounds across the three days instead of restarting every session.

    1. Quick start¶

    cd <package root>/notebooks
pip install -r requirements.txt
apt-get install -y fonts-hosny-amiri        # Lab 3 only; see §6
jupyter lab                                  # or: jupyter notebook

    Open a starter, Run All, and work through the # TODO blocks. A starter notebook runs clean on a fresh kernel — no cell errors before you have written anything; each TODO prints the shape and the numbers you should end up with.

    To re-execute everything headlessly (this is exactly how the shipped solutions were produced):

    cd <package root>/notebooks
for nb in lab1_*_solution lab2_*_solution lab3_*_solution \
          lab4_*_solution lab5_*_solution lab6_*_solution; do
  jupyter nbconvert --to notebook --execute --inplace "$nb.ipynb"
done

    Order matters once. Lab 6 imports story/tayseer_storyboard.py, which Lab 5 writes. Run Lab 5 before Lab 6. Labs 1–4 are independent of each other.

    2. What is in this folder¶

    Path What it is

    lab2_chart_selection_starter/solution.ipynb Chart chooser and the first honest charts
    lab3_declutter_redesign_starter/solution.ipynb Before/after redesign, colour, Arabic RTL

    tayseer_viz.py is deliberately thin. It holds the plumbing that every lab shares — the Okabe–Ito palette, the decluttered matplotlib theme, the correctly-implemented non-additive measures, one principle-compliant chart function, and the Arabic reshaping/bidi helpers — so each notebook stays about its teaching point.

    4. The measure rules — read this before editing anything¶

    This is the single error the course exists to prevent, and every notebook enforces it.

    Class Columns Rule
    Additive transactions, complaints SUM at any grain
    Semi-additive unique_users SUM within a month, never across months
    Non-additive digital_adoption_pct, cost_per_txn_sar, csat, avg_completion_min, sla_met_pct never AVERAGE — recompute from components

    The weight is not the same for every non-additive measure. It comes from data/supporting/kpi_targets.csv, which is the programme's semantic layer:

    KPI Formula Weight
    KPI-01 Digital adoption % SUM(adoption/100 × unique_users) / SUM(unique_users) × 100 unique_users
    KPI-02 Cost per transaction SUM(cost × transactions) / SUM(transactions) transactions
    KPI-03 CSAT SUM(csat × transactions) / SUM(transactions) transactions
    KPI-04 Avg completion time SUM(minutes × transactions) / SUM(transactions) transactions
    KPI-05 SLA met % SUM(sla × transactions) / SUM(transactions) transactions

    Adoption is a property of users (did this person go digital?); cost, satisfaction, completion time and SLA are properties of transactions. tayseer_viz implements each one and refuses to roll up a non-additive column without its declared weight:

    import tayseer_viz as tv
df = tv.load_facts()
latest = df[df.month == df.month.max()]

tv.adoption(latest)        # 63.84  — correct (KPI-01)
latest.digital_adoption_pct.mean()   # 61.19  — the averages-of-averages bug
tv.by(latest, "region", "cost_per_txn_sar")   # correct at any grain

    6. Arabic and RTL (Lab 3, task 6)¶

    matplotlib will draw Arabic as disconnected letters in left-to-right order unless you reshape and bidi the string first, and it needs a font that actually carries Arabic glyphs. Both are handled by tayseer_viz:

    ok, font = tv.setup_arabic()       # registers an Arabic font; returns (True, 'Amiri')
ax.set_title(tv.ar("نسبة التبني الرقمي"), **tv.arabic_kwargs())

    setup_arabic() looks for Amiri, then Scheherazade, then KacstOne, then FreeSerif. If none is present, or arabic-reshaper / python-bidi are missing, it returns False and emits a warning — fall back to English labels and say so on the slide. Shipping tofu boxes or disconnected letters is worse than shipping English.

    Install a font with apt-get install -y fonts-hosny-amiri (or fonts-sil-scheherazade, fonts-kacst, fonts-noto-naskh-arabic). Verify with fc-list :lang=ar.

    The lab also teaches the two RTL rules that are not about glyphs: a ranking axis puts the first/best on the right, and a time axis runs right-to-left (ax.invert_xaxis()). Translating the labels without mirroring the axis produces a chart that reads backwards to an Arabic-first audience.

    7. Running the Dash app (Lab 4b)¶

    A Dash app cannot run inside a notebook cell, so Lab 4 writes it and then compiles and imports it to prove it is sound. To actually use it:

    cd <package root>/notebooks
python app/dashboard.py            # -> http://127.0.0.1:8050

    It demonstrates all four interaction patterns — a channel filter, click-to-cross- filter on the regional bar, a drill path (national → region → service category → channel) with a breadcrumb, and a measure toggle — plus a rls_scope() function that is the code equivalent of the Power BI RegionDirector row-level-security role.

    8. Static export of Plotly figures¶

    Plotly's PNG export (kaleido ≥ 1) requires a Chrome binary, which is not present in every training environment and cannot always be downloaded. The notebooks therefore:

    1. always write the interactive HTML, which is the real deliverable, and
    2. always render a matplotlib mirror of the same view as a PNG in out/.

    tv.save_plotly(fig, name) attempts the PNG and reports cleanly if it cannot. Nothing in out/ is missing as a result — lab2_q2_trend.png mirrors lab2_q2_interactive.html, and lab4_dashboard_static.png mirrors lab4_dashboard.html.

    9. Chart doctrine — what every figure in out/ obeys¶

    The notebooks are themselves an exhibit, so they follow the rules they teach:

    • bars start at zero; only line charts may truncate an axis
    • sorted by value wherever a ranking exists
    • direct labelling instead of legends
    • a reference line (target or national mean) wherever good/bad is the question
    • one accent colour carrying the argument, everything else grey
    • takeaway titles — the conclusion, not the topic
    • Okabe–Ito palette, colour-blind safe, with the message carried redundantly by position, a reference line and text as well as by hue
    • no dual axes, no 3D, no gauges, and no pie charts — except the two built deliberately for critique, in Lab 1 task 2 and Lab 1 task 4

    10. Known deviations from the INSTRUCTOR_PACKAGE¶

    Small, deliberate, and flagged in the notebooks where they occur:

    1. Asset substitution. bad_dashboard_m1.png (Lab 1) and cluttered_m3.png (Lab 3) are not shipped with the data package, so both are built in code inside the notebook. That makes the critique target reproducible and lets participants see each violation in the source.
    2. "Three regions" vs "five". Several expected-output blocks in the INSTRUCTOR_PACKAGE say three regions are below target. The data says nine are below target, five of those are stalled (Tier 1), and three are more than 9pp below. The notebooks use all three counts and name which is which; the story's ask is about the five stalled regions, matching README.md and validation_report.md.
    3. No March 2024 outage. Module 3's code example annotates a "March 2024 service outage" behind Najran's plateau. No such step change exists in tayseer_services.csv — Najran rises smoothly and flattens over the last nine months. Lab 3 annotates the nine-month stall, which the data does support.
    4. Adoption never crosses 65%. Module 2's expected output says national adoption goes "41% → 68%, crosses 65% in month 21". The data says 34.2% → 63.8%, never crossing. The notebooks use the data; the gap to target is the whole point of the story.
    5. Five Lab 2 questions, not four. lab2_questions.csv ships Q1–Q5 (Q5 is the thirteen-overlapping-lines / small-multiples question). Lab 2 covers all five.
