    MODULE 2 — Stationarity and Autocorrelation¶

    Header: Module 2 · "Stationarity and Autocorrelation" · Day 1, Hour 4 (theory, 65/35) + Day 1, Hour 5 = Lab 2 (15/85) · Maps to LO1 (primary), LO2 (differencing)

    Learning Objectives (verbatim)¶

    # Objective Maps to
    2.1 Define weak stationarity and identify sources of non-stationarity LO1
    2.2 Apply and reconcile ADF and KPSS tests LO1
    2.3 Apply regular and seasonal differencing to achieve stationarity LO1, LO2
    2.4 Compute and interpret ACF and PACF LO1
    2.5 Translate ACF/PACF signatures into candidate ARIMA orders LO1, LO2

    Purpose/framing line for title slide: "Classical models assume stationarity — diagnose it, transform to it, then read autocorrelation to fingerprint the model." Business relevance: a model fit to non-stationary data produces "confidently wrong forecasts" — projects yesterday's level/variance into a future where both moved; mistaking trend for stationary mean is called "the single most expensive analytical error" in demand/economic forecasting.

    Technical Content¶

    1. Stationarity, precisely - Weak (covariance) stationarity = 3 things constant over time: mean, variance, autocovariance at each lag (depends only on gap k, not position). - Matters because ARIMA-family models estimate ONE parameter set assumed to hold throughout. - Three sources of non-stationarity, each with its remedy: - Trend (mean changes) → differencing or detrend by modeling trend - Seasonality (mean changes periodically) → seasonal differencing or model the season - Changing variance (heteroskedasticity) → variance-stabilizing transform (log, Box-Cox) - Tayyar has all three: growth trend, multi-period seasonality, summer-amplified variance. Fix order: stabilize variance (log, Module 1) → then difference.

    2. Testing stationarity: ADF and KPSS — opposite nulls - ADF: null = "has a unit root" = non-stationary. Small p (< 0.05) → reject non-stationarity → evidence of stationarity. - KPSS: null = "is stationary." Small p (< 0.05) → reject stationarity → evidence of non-stationarity. - The 2×2 reconciliation table (verbatim):

    KPSS says stationary KPSS says non-stationary
    ADF says stationary Stationary — proceed Difference-stationary; try differencing
    ADF says non-stationary Trend-stationary; detrend Non-stationary — difference and re-test
    • Teaching point: using both is best practice because they can disagree — the disagreement itself is informative (trend-stationary vs difference-stationary). Never rely on one test or eyeballing alone.

    3. Differencing: regular and seasonal - Regular: ∇y_t = y_t − y_{t−1} removes trend → gives d in ARIMA. - Seasonal: ∇m y_t = y_t − y removes seasonal pattern of period m → gives D in SARIMA. - Discipline: - Difference as little as possible. Over-differencing injects artificial negative autocorrelation at lag 1, inflates variance. Signature: lag-1 ACF strongly negative (< −0.5), noisier-than-needed series. - Order of operations: seasonal differencing first, re-test; regular difference only if still non-stationary. Most series need d ≤ 2, D ≤ 1. - pmdarima.arima.ndiffs / nsdiffs estimate d, D from tests — "automation proposes, the analyst disposes."

    4. ACF and PACF: the model fingerprint - ACF(k) = correlation between y_t and y_{t−k}. PACF(k) = correlation at lag k after removing intervening lags' effect. - Fingerprint table (verbatim):

    Pattern ACF PACF Suggests
    AR(p) tails off (decays) cuts off after lag p AR order p
    MA(q) cuts off after lag q tails off MA order q
    ARMA(p,q) tails off tails off mixed; use information criteria
    Seasonal spike at lag m, 2m, … spike at m seasonal terms
    • "Cuts off" = drops inside significance band (±1.96/√n).
    • Tayyar's daily-differenced series: expect spike at lag 24 and multiples.

    Design Principles / Best Practices / Common Mistakes¶

    Principles - Transform for variance, difference for mean — do them in that order. - Stationarity is a means, not the goal — invert every transform to forecast on the original scale. - Autocorrelation is structure, not noise — strong ACF is exploitable signal; flat ACF ≈ 0 everywhere = already white noise, nothing beats naive.

    Common mistakes (each planted in Lab 2 starter) 1. Interpreting ADF's null backwards ("p > 0.05 so it's stationary"). 2. Over-differencing until stationary but the model is worse. 3. Differencing before stabilizing variance — heteroskedasticity survives. 4. Reading the ACF of a non-stationary series (slow, linear decay) and mistaking it for high AR order rather than a trend to difference. 5. Ignoring seasonal spikes at lag m because default lags=20 doesn't reach 24. 6. Running tests on log series but forecasting/evaluating on raw series without back-transforming.

    Production considerations: Re-run stationarity diagnostics on a schedule (regime shift risk — tariff change, new industrial load). Persist chosen d, D, transform for reproducibility; drift in these choices is itself a monitored signal.

    def suggest_orders(series, m=24):
    d = ndiffs(s, test="adf")
    D = nsdiffs(s, m=m, test="ocsb")
    return {"d": int(d), "D": int(D), "m": m}

def make_stationary(series, d, D, m):
    """Seasonal difference FIRST, then regular. Minimal differencing."""
    for _ in range(D): s = s.diff(m)
    for _ in range(d): s = s.diff(1)

    Case Study — Forecasting a Non-Stationary Economic Indicator¶

    • Scenario: planning ministry forecasts monthly economic activity index for quarterly budgeting; analyst regressed index on trending oil-price, reported near-perfect fit that collapsed out of sample.
    • Business context: budget allocations move on these forecasts; spurious relationship → over-commitment.
    • Technical challenge: establish integration order of both series, difference to stationarity, only then assess genuine relationship.
    • Constraints: short monthly history (~120 points); strong annual seasonality; structural break at known policy change (must not blindly difference away).
    • Solution approach: (1) ADF/KPSS each series; (2) determine d for each; (3) seasonal differencing for annual pattern; (4) re-test relationship on stationary series; (5) discuss structural break — dummy vs split sample.
    • Discussion questions: Why does regressing two trending series give spurious high R²? How decide dummy vs model reset for the break? With 120 points, what limits differencing? When is slow ACF decay a sign to difference vs genuine long memory?

    MODULE 3 — ARIMA and Exponential Smoothing¶

    Header: Module 3 · "ARIMA and Exponential Smoothing" · Day 2, Hour 1 (ARIMA/SARIMA, 65/35) + Day 2, Hour 2 (ETS + Lab 3, 40/60) · Maps to LO2 (primary), LO3

    Learning Objectives (verbatim)¶

    # Objective Maps to
    3.1 Specify and fit ARIMA/SARIMA models with justified orders LO2
    3.2 Incorporate exogenous regressors with SARIMAX LO2, LO3
    3.3 Select an exponential-smoothing/ETS specification from the taxonomy LO2
    3.4 Diagnose model adequacy from residuals LO2, LO5
    3.5 Compare ARIMA and ETS and choose per situation LO2, LO6

    Framing: classical models remain the model to beat in regulated/safety-critical settings — "the forecast rose because the level term updated and the summer seasonal factor kicked in" is accepted by a control-room engineer; "the gradient boosting said so" is not.

    Technical Content¶

    1. The ARIMA family - AR(p): y_t depends linearly on its own p past values. I(d): d differences to reach stationarity. MA(q): y_t depends on last q forecast errors (shocks). - SARIMA(p,d,q)(P,D,Q)m adds seasonal AR(P), seasonal diff(D), seasonal MA(Q) at period m. For hourly Tayyar with daily cycle, m=24. - Practical constraint: m=24 (or 168) → state space grows, estimation slows sharply. Practitioners often model a daily-aggregated series with m=7 in SARIMA, leave sub-daily to ML (Module 4) — "where classical methods strain."

    2. Order selection - Read correlograms (Module 2): AR from PACF cutoff, MA from ACF cutoff, seasonal terms from spikes at m. - Minimize information criterion (AICc for small samples, BIC for parsimony) across candidate grid. pmdarima.auto_arima automates stepwise search but analyst constrains it (max_p, seasonal=True, m, D) and confirms winner's residuals. - Never compare AIC across different d. Lower is better; differences under ~2 not meaningful.

    3. SARIMAX: exogenous regressors - Load driven by temperature (available as forecast at prediction time). SARIMAX = SARIMA + linear function of X_t. - Tayyar adds temperature + calendar dummies (weekend, Ramadan, Eid). - Two cautions: (1) need FUTURE regressor values at forecast time (weather forecast — its error propagates); (2) regressors must be genuinely exogenous/available ahead, or it's a leak.

    4. Exponential smoothing and ETS - Forecast as weighted average of past observations with exponentially decaying weights. - Ladder: SES (level only, flat forecast) → Holt (level+trend; damped_trend=True prevents implausible long-horizon extremes — "almost always the safer production choice") → Holt-Winters (level+trend+season, additive or multiplicative). - ETS taxonomy: (Error, Trend, Seasonal), each ∈ {None, Additive, Multiplicative}, e.g. ETS(A,Ad,M) = additive error, additive damped trend, multiplicative season. - statsmodels.ETSModel (or sktime/statsforecast automated selection) picks spec by AICc. ETS handles single seasonal period cleanly; multiple seasonalities need TBATS or ML route.

    5. Residual diagnostics - Fitted model trustworthy only if residuals are white noise. Checks: - Residual ACF / Ljung-Box: null = "residuals independent." Small p → autocorrelation remains → raise an order. - Residual mean ≈ 0 (no bias), roughly constant variance (transform worked). - Approximate normality (histogram/Q-Q) — matters for interval validity more than point forecast. - plot_diagnostics() gives all four panels at once. Diagnostics are mandatory, not optional — "an un-diagnosed auto_arima result is a liability."

    Design Principles / Best Practices / Common Mistakes¶

    Common mistakes 1. Comparing AIC across models with different differencing orders. 2. Trusting auto_arima without checking residual autocorrelation (Ljung-Box). 3. Forgetting exogenous regressors need future values at forecast time (temperature leak/unavailable). 4. Un-damped Holt trend → absurd long-horizon forecasts. 5. Fitting multiplicative seasonality/ETS to a series containing zeros. 6. Reporting forecasts on log scale, or back-transforming a log-mean without bias correction.

    Production considerations: Refit on a schedule (parameter drift); persist orders, treat re-selection as monitored event. Classical intervals are cheap and honest — the baseline fancier methods must beat. For thousands of series, prefer automated ETS (statsforecast, vectorized/fast) over per-series hand-tuning.

    Case Study — Day-Ahead Load Forecasting for Reserve Margins¶

    • Scenario: Tayyar must deliver day-ahead daily-peak forecast with trustworthy interval (reserve margin set from upper bound); engineers reject uninterpretable models.
    • Business context: interval, not just point, drives money and reliability; too wide = wasteful reserves; too narrow = load-shedding risk.
    • Technical challenge: choose SARIMAX (interpretable, interval-native, temperature-aware) vs ETS (fast, robust, no exog) for strongly seasonal + weather-driven series; defend to non-statisticians.
    • Constraints: publication deadline (minutes); temperature only as forecast (error must be acknowledged); model must be explainable component-by-component.
    • Solution approach: (1) ETS as no-exog baseline; (2) SARIMAX adding temp+calendar; (3) diagnose both; (4) compare on held-out window with intervals AND coverage; (5) recommend SARIMAX if temperature materially helps and coverage holds, else simpler ETS.
    • Discussion questions: How does temp-forecast error propagate into the load interval, and how would you widen the interval? When ship simpler ETS despite SARIMAX's lower point error? Explain SARIMAX to control-room engineer in one sentence? What monitoring signals orders gone stale?

    Technical Content¶

    1. Forecasting as supervised learning (reduction) - Core move: build a feature row for y_t using info strictly before t — lags (y_{t-1}, y_{t-24}, y_{t-168}), rolling stats of the past, calendar attributes of t, exogenous X_t (temperature known at forecast time). - sktime.make_reduction / skforecast automate "reduction to tabular ML." Peril: split, features, validation must all respect time.

    2. The feature families - Lag features: y at 1, 2, 3, 24, 48, 168 hours ago — chosen from the ACF (significant lags = useful features). - Rolling-window statistics: mean/min/max/std over past 24h, 168h — smoothed level and volatility. Critical: windows must end BEFORE the target (.shift(1) after rolling) or leakage. - Calendar features: hour-of-day, day-of-week, month, is-weekend (Fri–Sat), is-Ramadan, is-Eid, is-National-Day — cyclic (sin/cos) or categorical. - Fourier terms: pairs of sin(2πkt/m), cos(2πkt/m) compactly encode smooth seasonality of period m with few columns — the ML way to represent multiple seasonalities (daily+weekly+annual) jointly, which MSTL/SARIMA cannot. - Exogenous & interactions: temperature, explicit interactions (temp × is_afternoon) capturing the nonlinear AC-driven peak.

    3. Multi-step strategies: recursive vs direct - Recursive: one model per one step; feeds predictions back as lags. Compact, but errors compound; predicted lags differ in distribution from true lags. - Direct: separate model per horizon (h=1..24), predicts directly from origin features. No compounding, but H models, no cross-horizon coherence guarantee. - Hybrid/multi-output (DirRec, or single model with horizon as feature) trades off. - Decision rule: short horizons + strong autocorrelation → recursive; longer horizons/compounding risk → direct. Tayyar's 24h day-ahead: direct-per-horizon (skforecast.ForecasterDirect) is robust default.

    4. Gradient boosting for forecasting - Trees CANNOT extrapolate beyond training range — will never forecast demand higher than any seen. Mitigate: (a) model a differenced/detrended target so level trend handled outside trees, or (b) include a trend feature (time index) with care. - Tune with time-series cross-validation (Module 6), never random folds. Key knobs: num_leaves, learning_rate + n_estimators, min_child_samples, regularization. - For many series, train one global model with series ID as categorical — shares strength across series, often beats per-series models.

    Design Principles / Best Practices / Common Mistakes¶

    Principles - Every feature must be computable at forecast time using only the past — "the module's whole ethic." - Choose lags from the ACF, not a guess. - Prefer differenced/relative targets so trees operate in a stationary, interpolable range.

    Common mistakes (planted in Lab 4 starter) 1. train_test_split(shuffle=True) on time series — cardinal leak; test rows precede train rows. 2. Rolling features including the current row (forgot .shift(1)) — target leaks into its own feature. 3. Scaling/encoding fit on the whole dataset before split — future's statistics contaminate the past. 4. Using a future value of an exogenous driver not known at prediction time. 5. Ignoring trees can't extrapolate, then surprised model under-forecasts a record heatwave. 6. Reporting feature importance as causal ("hour_of_day causes demand") rather than associational.

    Production considerations: feature pipelines identical in training and serving (shared, versioned feature module — training/serving-skew lesson). Recompute lags from reliable recent-history store at serving time. Retrain on cadence; monitor feature drift; log feature values with prediction for debuggability.

    Framing: "A point forecast is a lie by omission... The interval IS the product." Reserve margin is sized off the UPPER bound of the day-ahead forecast, not the mean.

    Technical Content¶

    1. Why a point forecast is not enough - Two forecasts can share a mean of 50,000 MW while one is near-certain and the other spans ±8,000 MW — completely different reserve decision. - Reframing: "forecast the distribution, then let the decision pick the quantile it needs." Cost-asymmetric decisions (under-forecasting far more expensive) want a specific quantile, not the mean. - Module ethic: "report uncertainty, and then prove it is honest."

    2. Prediction intervals vs confidence intervals - Confidence interval: uncertainty about a parameter (mean level). Prediction interval: uncertainty about a future observation (parameter uncertainty + irreducible noise) — always wider. - Forecasting almost always wants prediction intervals. Classical models produce these analytically (conf_int/summary_frame) but trust distributional assumptions (Gaussian, constant variance) — violated by Tayyar's summer heteroskedasticity, motivating empirical cross-checks.

    3. Quantile regression and the pinball loss - Formula: L_τ(y, ŷ) = max( τ·(y − ŷ), (τ − 1)·(y − ŷ) ) - Asymmetric penalty: for τ=0.9, under-prediction costs 0.9/unit, over-prediction costs 0.1/unit — minimizer sits at the 90th percentile. - Fit one model per quantile (τ ∈ {0.05, 0.5, 0.95}); the 0.05/0.95 pair IS a 90% interval. LightGBM: objective="quantile", alpha=τ. Pinball loss is also the evaluation metric for Module 6. - Quantile crossing: independently-fit quantile models can cross (predicted 0.95 < 0.50) — incoherent distribution. Repair: sort predicted quantiles per row (isotonic) or fit monotone-constrained model.

    4. Conformal prediction: coverage you can guarantee - Split (inductive) conformal prediction — model-agnostic wrapper guaranteeing marginal coverage under exchangeability assumption: 1. Split history into training set + held-out calibration set. 2. Fit point model on training; on calibration compute nonconformity scores, typically |y − ŷ|. 3. Take the ⌈(n+1)(1−α)⌉/n empirical quantile q̂ of those scores. 4. Interval for new point: ŷ ± q̂ — guaranteed ≈(1−α) marginal coverage. - For time series, plain exchangeability is strained (serially correlated, drifting residuals) → use EnbPI or adaptive conformal (ACI), updating q̂ online as coverage errors accumulate. - Conformalised Quantile Regression (CQR): conformalizes the quantile-model interval — sharpness of quantile regression + coverage guarantee of conformal. Taught as the default for Tayyar.

    Design Principles / Best Practices / Common Mistakes¶

    Principles - Coverage first, sharpness second — an interval missing its coverage target is wrong at any width. - Calibrate on data the model never trained on — conformal/coverage estimates need a held-out window respecting time. - Decisions consume quantiles, not means — elicit cost asymmetry, report the needed quantile.

    Common mistakes (planted in Lab 5 starter) 1. Reporting a confidence interval where a prediction interval is required (far too narrow). 2. Trusting an analytic Gaussian interval on a heteroskedastic series — coverage collapses in summer. 3. Estimating coverage on the training set (optimistic) instead of held-out window. 4. Letting quantile models cross and shipping an incoherent distribution. 5. Using vanilla i.i.d. conformal on strongly autocorrelated series, over-trusting the guarantee. 6. Comparing two methods on sharpness alone while one silently under-covers.

    Production considerations: monitor rolling empirical coverage as first-class metric (drift 90%→80% signals staleness before point error degrades). Recalibrate conformal quantiles on schedule; persist calibration window and q̂. Expose downstream quantiles (p50, p90, p95) as explicit service outputs.

    def cqr_calibrate(lo_cal, hi_cal, y_cal, alpha=0.10):
    """Nonconformity = how far the truth fell OUTSIDE the [lo, hi] band."""
    scores = np.maximum(lo_cal - y_cal, y_cal - hi_cal)   # >0 when outside
    n = len(scores)
    k = int(np.ceil((n + 1) * (1 - alpha)))
    q_hat = np.sort(scores)[min(k, n) - 1]
    return float(q_hat)

def cqr_apply(lo, hi, q_hat):
    """Widen the raw quantile interval by the calibrated correction."""
    return lo - q_hat, hi + q_hat

    Learning Objectives (verbatim)¶

    Technical Content¶

    1. Why a single split is not evidence - One split estimates skill from one realization of the future; test-week luck can flip rankings. - Backtesting repeats evaluation over many origins and aggregates errors → a distribution of skill, not a point estimate. Non-negotiable: at every origin the model may use only data available at that origin (Module 4's leakage ethic elevated to the evaluation loop).

    2. Backtesting schemes: rolling vs expanding origin - Expanding window (anchored): training set grows, always starts at beginning, ends at current origin. Uses all history; mimics a system that never forgets. Preferred when more data always helps and process is stable. - Rolling window (sliding): fixed-length training window slides forward, drops oldest data. Mimics adapting to recent regime, forgetting stale history. Preferred when process drifts (new industrial load, tariff change). - Parameterized by forecast horizon (h, e.g. 24h) and step (origin jump per fold). Refinement: gap — if target uses features from recent past, leave a gap between train/test so no feature straddles the boundary. sktime's ExpandingWindowSplitter/SlidingWindowSplitter + evaluate implement this correctly; "hand-rolled loops are where leaks creep back in."

    3. Point-accuracy metrics and their failure modes — full table (verbatim)

    Metric Formula (sketch) Strength Fails when
    MAE mean |y − ŷ| same units, robust not comparable across series of different scale
    RMSE √mean (y − ŷ)² penalises large misses dominated by outliers; scale-bound
    MAPE mean |y − ŷ|/|y| scale-free %, intuitive explodes near zero; asymmetric (over-forecasts capped at 100%)
    sMAPE symmetric % bounded still unstable near zero; awkward interpretation
    MASE MAE / MAE of seasonal-naive scale-free, symmetric, defined at zero needs a sensible baseline period m
    • MASE = the cross-series workhorse: MASE < 1 beats naive; = 1 ties; > 1 naive (free) was better. Always report MASE alongside a % metric.

    4. Evaluating probabilistic forecasts - Pinball/quantile loss aggregated across quantiles — a proper scoring rule (minimized by the true distribution), rewards honest calibration not just a good median. - Empirical coverage vs nominal (does 90% interval contain truth 90% of the time across all origins). - Interval width/sharpness — among calibrated models, narrower wins. - CRPS (continuous ranked probability score) when full predictive distribution available — integral of pinball over all quantiles, "the gold-standard single number for probabilistic skill."

    5. Comparing models: is the difference real? — Diebold-Mariano - DM test compares the loss-differential series (per-origin loss of A minus B), tests null that mean is zero. - Significant result (small p) → one model genuinely more accurate on this series/horizon. Non-significant → pick the simpler/cheaper one, "because you cannot distinguish them." - Cautions: DM compares two models (use corrections/Model Confidence Set for many); assumes loss-differential is covariance-stationary; needs enough origins for power. - Decision rule: statistical significance gates model promotion — a 0.1% MAE "win" failing DM does not justify shipping added complexity.

    Design Principles / Best Practices / Common Mistakes¶

    Principles - Always beat a named baseline — report seasonal-naive first; a model that can't beat it is not a model. - The backtest is the product — reproducibility (fixed splits, seeds, pinned versions) is what makes the report evidence rather than anecdote. - Refit inside the loop — for honest production-behavior estimate, refit (or re-select) at each origin as production would; a fitted-once model flatters itself.

    Common mistakes (planted in Lab 6 starter) 1. Random k-fold cross-validation on time series — the cardinal leak, again. 2. Fitting once on all data then "backtesting" by predicting past points already seen. 3. Reporting MAPE on a series with near-zero values (spikes to thousands of %). 4. Comparing models on different test windows and declaring a winner. 5. No baseline, so a mediocre model looks impressive in isolation. 6. Declaring a winner on a fraction-of-a-percent MAE gap without a significance test.

    Production considerations: automate backtest as scheduled job; rising rolling MASE = early drift alarm. Version backtest config with model for reproducibility. Store per-origin errors, not just aggregate, to diagnose which conditions (heatwaves, Eids) a model handles poorly.

    def mase(y_true, y_pred, y_train, m=24):
    """MAE(model) / MAE(seasonal-naive on the training set). <1 beats naive."""
    num = np.mean(np.abs(np.asarray(y_true) - np.asarray(y_pred)))
    diffs = np.abs(y_train[m:].to_numpy() - y_train[:-m].to_numpy())
    denom = np.mean(diffs)
    return float(num / denom) if denom > 0 else np.inf

    def diebold_mariano(y_true, pred_a, pred_b, h=1, power=2):
    e_a = np.abs(y_true - pred_a) ** power
    e_b = np.abs(y_true - pred_b) ** power
    d = e_a - e_b                      # loss differential
    gamma0 = np.var(d, ddof=0)
    gamma = [np.cov(d[k:], d[:-k])[0,1] for k in range(1, h)]
    var_d = (gamma0 + 2 * sum(gamma)) / n
    dm_stat = d_bar / np.sqrt(var_d) if var_d > 0 else 0.0
    p_value = 2 * (1 - stats.norm.cdf(abs(dm_stat)))
    winner = "A" if d_bar < 0 else "B"

    Design Principles / Best Practices / Common Mistakes¶

    Principles - Select for the decision, not the leaderboard — metric must match the decision's cost function. - The simplest model that meets the constraints wins — complexity justified only by a DM-significant, decision-relevant gain. - A recommendation includes its own limits — state where the model loses and what you monitor; "that candour is what earns adoption."

    Common mistakes 1. Picking the lowest-MAE model regardless of deadline, explainability, or cost asymmetry. 2. Optimizing symmetric error when the decision's costs are asymmetric. 3. Shipping an accurate model with no fallback for calendar weeks it demonstrably fails. 4. Presenting a point forecast to a decision that is inherently a quantile decision. 5. A pipeline that runs only on the author's laptop — "irreproducible evidence is no evidence." 6. Communicating in model jargon ("MASE 0.54") instead of decision terms ("beats the free forecast by 46%").

    Production considerations: selected model needs a monitoring contract: rolling MASE + coverage tracked per week, drift alarms, documented retrain cadence, champion/challenger setup so next candidate is always backtested against incumbent. Decision record is a living document, revisited when a monitored metric breaches threshold.
