    Facilitator Run-Sheet — SDA-DSC-212 Time Series Analysis and Forecasting¶

    3 days × 5 learning hours = 15 hours. Each "hour" is 50 minutes of instruction plus a 10-minute buffer. Schedule the long break around Dhuhr. Deliver in Arabic or English; keep all code, column names and commit messages in English — mixed-language identifiers break tooling in Saudi enterprise environments.

    The one thing to hold on to¶

    Every module advances the same artefact: Tayyar, a day-ahead load-forecasting service for the Central Operating Area. Never introduce a throwaway airline-passengers toy set beyond one warm-up plot. The golden thread is what makes the Day-3 backtest report and the capstone achievable in fifteen hours.

    The non-negotiable is temporal leakage. Publish the leakage-smells poster (instructor/posters/P1_leakage_smells.pdf) on the wall and point at it every single time a random split appears on anyone's screen.

    T-minus one week¶

    • Fork or clone the course repo; push the checkpoint tags lab1-start … lab7-start and lab1-solution … lab7-solution, and the sim-* branches: sim-gap, sim-agg, sim-spurious, sim-overdiff, sim-aic-trap, sim-nodamp, sim-centred-roll, sim-heatwave, sim-hetero, sim-train-coverage, sim-fit-once, sim-lucky-split, sim-leaderboard, sim-asymmetric.
    • Regenerate the datasets: python tools/make_tayyar_data.py. Confirm 26,280 clean rows, peak ≈ 57.9 GW, mean ≈ 33.1 GW.
    • Run python tools/run_reference.py and check every number against reference_results.json. This is your answer key and the source of every figure in the deck.
    • Execute all seven solution notebooks end to end on a clean machine and on the Colab fallback (data pre-loaded to a mounted drive). Budget: Lab 6 takes about 11 minutes.
    • Verify the two fragile installs, pmdarima and Prophet, on both Windows and macOS. Pin working versions in the lock file. Neither is required by the core labs — the course runs on statsmodels, LightGBM and scikit-learn — but participants will try to install them.
    • Time-box Lab 4 (feature engineering) and Lab 6 (backtesting). Confirm git checkout labN-start fast-forwards a straggler cleanly.
    • Print the five A4 posters: instructor/posters/ALL_POSTERS.pdf.
    • Prepare the shared leaderboard for the Day-3 bake-off (MASE, coverage, pinball).

    T-minus two days — participant email¶

    • Python 3.12, git, a GitHub account.
    • conda/uv environment; pip install pandas numpy matplotlib statsmodels scipy scikit-learn lightgbm jupyter
    • VS Code (or preferred IDE) with the Python extension.
    • Clone the course repo and run make doctor — it prints ✓/✗ per package.
    • Confirm the classroom network allows github.com and PyPI, or configure a mirror. Pre-download the datasets to the shared drive for offline rooms.

    Day 1 — Seeing the Signal¶

    Hour Session Mode Theory/Lab Facilitator focus
    1 Why time series breaks ordinary ML · course kickoff interactive lecture + failure story 80/20 Tell the failure story as a story, not a slide. Ask who has shipped a model whose live accuracy did not match validation. Almost every hand goes up.
    2 Decomposition: trend, seasonality, remainder (M1) lecture + live STL demo 65/35 Do the clean-and-decompose live in under 8 minutes. Deliberately skip asfreq once, show the seasonal smear, then fix it.
    3 Lab 1 — load, index, resample, decompose guided lab, pairs 15/85 Circulate. Do not warn anyone about the messy timestamps. Let a pair discover the silent row loss.
    4 Stationarity and autocorrelation (M2) lecture + ACF/PACF walkthrough 65/35 Run the verdict-reconciliation drill: call p-value pairs, room says the reconciled verdict aloud. Quiz the ADF/KPSS nulls cold.
    5 Lab 2 — the stationarity report guided lab, pairs 15/85 Watch for pairs who difference until ADF is happy and stop thinking. Send them to the lag-1 ACF.

    End of Day 1 deliverable. A clean hourly Tayyar series with decomposition plots and a stationarity report (ADF/KPSS, ACF/PACF). This is capstone milestone M-A — spot-check the index, the gap policy and the reported strengths before anyone leaves.

    Activities available: decomposition read-aloud (15 min) · "component or covariate?" card sort (10 min) · ACF/PACF speed round (15 min) · verdict reconciliation drill (10 min).

    Day 2 — Building Forecasts¶

    Rotate the pairs. Put a strong-statistics participant with a strong-ML participant — the M3→M4 bridge is exactly where that skill transfer pays off.

    Hour Session Mode Theory/Lab Facilitator focus
    1 ARIMA and SARIMA (M3) lecture + demo 65/35 Flag the m = 24 wall early and say it is deliberate. Do not hide that the fitted SARIMAX fails its own Ljung-Box test — that honesty is why the ML route exists.
    2 ETS (M3) + Lab 3 micro-lecture + guided lab 40/60 Run "explain it to the control room": one sentence each, read aloud, cut any sentence containing the word "parameter".
    3 Feature-based ML forecasting (M4) lecture + feature-build demo 60/40 Run "what does this feature see?" — eight candidates, thumbs up/down. Include the ambiguous one (temperature) and let the argument happen.
    4 Lab 4 — LightGBM forecaster guided lab, pairs 10/90 Protect the full 50 minutes. Run task 1 as a race: first pair to name both planted leaks precisely wins.
    5 Probabilistic forecasting (M5) + Lab 5 start lecture + lab 45/55 End the day after Lab 5 task 3, with the room holding an interval that visibly under-covers. They will think about it overnight.

    End of Day 2 deliverable. SARIMAX and ETS baselines plus a LightGBM feature-based forecaster, all producing 24-hour forecasts. Capstone milestone M-B — the leak check must pass.

    Day 3 — Trust and Selection¶

    Hour Session Mode Theory/Lab Facilitator focus
    1 Intervals and calibration (M5) + Lab 5 finish micro-lecture + lab 35/65 The CQR fix lands hard this morning because they slept on a broken interval. Then show the conditional-coverage table — 0.90 marginal hides 0.845 on peak hours.
    2 Backtesting and forecast evaluation (M6) lecture + backtest dissection 55/45 Run "baseline first" (10 min): every pair hand-computes the seasonal-naive error for one day. That number is what everything must beat.
    3 Lab 6 — rolling-origin backtest guided lab, pairs 10/90 Protect the full 50 minutes. Run the shared leaderboard on the projector. Then the significance debate: class predicts the DM verdict by eye, then runs it.
    4 Case study + capstone assembly (M7) case discussion + project work 20/80 Start on time — cut discussion, not build time. Collect repository URLs at the END of this hour so you can spot-check backtests before the demos.
    5 Capstone demos + assessment + wrap-up presentations 15/85 Five minutes each. Grade from the repository first: clone, run the one command, check the numbers regenerate.

    End of Day 3 deliverable. A rolling-origin backtest report with calibrated intervals, a model-selection decision, and the capstone demo. Milestones M-C, M-D, M-E.

    Pace control¶

    • If you are behind: compress the M6 theory — it lands through the lab anyway. Reduce Lab 7 to two constraint scenarios and demo the third.
    • Never drop the backtest report. It is the course's deliverable and its thesis made visible.
    • If the cohort is strong: pull the multi-area global model into the capstone main scope and add a fourth model family (TBATS or Prophet) to the bake-off.
    • If the cohort is weak: keep every lab, cut every optional activity, and hold the golden thread.
    • Publish checkpoint tags so stragglers fast-forward: git checkout lab4-start.

    Common issues and their resolutions¶

    Issue Frequency Resolution
    pmdarima / Prophet install fails on Windows or macOS wheels High Pin known-good versions; fall back to the provided Colab notebooks — no penalty. Neither is required by the core labs.
    auto_arima or SARIMAX with m=24 runs for minutes High Model the daily series with m=7; leave sub-daily structure to the ML route. This is a deliberate, teachable wall.
    ADF and KPSS null hypotheses read backwards High The 2×2 poster. Quiz it cold. ADF small p = stationary; KPSS small p = non-stationary.
    Suspiciously low MAPE (a leak survives) High Re-run assert_no_leakage; check .shift(1) on every rolling feature and that no shuffle split remains.
    KSA weekend coded as Saturday–Sunday Medium Friday(4) and Saturday(5) in pandas dayofweek, where Monday = 0. Check the calendar join.
    Backtest scores in-sample (MASE ≈ 0) Medium Training data at every origin must end at or before that origin. Never predict points the model trained on.
    Confidence versus prediction interval confusion Medium A prediction interval includes the noise, so it is wider. Forecasting always wants it.
    Rolling backtest with SARIMAX refit is slow Medium Expected. Cache the cheap models, parallelise the folds, shrink the candidate grid, or state a coarser retrain cadence and quantify its effect.
    Quantile crossing (q95 < q50) Low Sort the per-row quantiles, or use a monotone constraint.
    Coverage good marginally, fails on hot afternoons Low Report coverage by hour band. Switch to adaptive conformal (ACI/EnbPI).
    MSTL panels come out blank Low MSTL drops the DatetimeIndex from its components, and STL cannot handle NaN. Interpolate first, then reattach the index before plotting.

    Discussion prompts (use during transitions)¶

    1. What is the most expensive forecasting error you have seen reach a decision — and would a backtest have caught it?
    2. Your model's MAPE is 2.3%. Your interval covers 90% on average but 85% on the hottest afternoons. Which number does the control room feel?
    3. When is the free seasonal-naive forecast the right answer, and how would your report prove it?
    4. Who owns the reserve-margin quantile — forecasting, operations, or risk? What does your answer imply about which number you publish?
    5. If the repository is the audit evidence for an accuracy claim, what does your current backtest testify?

    Wrap-up — Day 3, final 15 minutes¶

    • One slide mapping each capstone requirement to the module that taught it: decomposition → M1, stationarity → M2, classical → M3, features → M4, intervals → M5, backtest → M6, selection → M7.
    • Reinforce the single thesis one last time: respect the arrow of time, so every reported accuracy number would survive contact with the future. The leakage-safe features, the time-aware backtest and the calibrated intervals are three faces of that one discipline.
    • Forward pointer: SDA-DSC-311 builds on this pipeline. SDA-DSC-213 Experimentation and Causal Inference is the sibling "what actually works" skill that forecasting alone cannot answer.
    • Collect: repository URLs, BACKTEST_REPORT.md, DECISION_RECORD.md, BENCHMARKS.md. Issue Forecasting-badge recommendations within five working days.
