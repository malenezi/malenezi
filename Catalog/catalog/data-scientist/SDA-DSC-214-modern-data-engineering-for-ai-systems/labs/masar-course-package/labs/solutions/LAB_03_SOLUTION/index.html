    LAB 03 — INSTRUCTOR SOLUTION GUIDE¶

    Build the ELT Pipeline to silver.trips¶

    Field Value
    Lab LAB-03 (3a + 3b) · Module 3 · Day 2 Hours 3 and 5 · 90 minutes total · pairs
    Tags lab3-start (3a) → lab3a-solution; lab3b-start (3b) → lab3-solution
    Room setup Projector on a terminal running dbt run --select silver_trips with the Delta history query aliased; whiteboard timeline for the late-arrival drill (event time vs arrival time on two parallel axes)
    Pre-flight On a clean clone: dbt debug green, dbt deps resolves dbt_utils, the late-arrival fixture exists at data/fixtures/late_trips/trips_late_2026-06-02.csv and contains 1 trip whose pickup_ts is on 2026-06-01
    Pairing Deliberately pair a strong-SQL participant with a strong-Python/Spark participant; 3a rewards SQL, 3b rewards pipeline thinking

    Scale note. Figures quoted in this document assume the full-scale generator run (--scale 1.0); the shipped sample is --scale 0.15 — 7,230 trips/day over 5 days (36,150 trips), 873,763 GPS pings, 3,450 drivers, 3,864 vehicles, 48 zones. Grains, ratios and file-count reductions hold at either scale; absolute row counts do not.

    1. Reference solution¶

    1.1 dbt/masar/profiles.yml and dbt_project.yml¶

    As printed in the participant guide. Two things to verify in every pair's terminal:

    echo $DBT_PROFILES_DIR          # must be .../dbt/masar
grep -A2 'method' dbt/masar/profiles.yml    # must read: method: session

    1.2 Sources — models/staging/masar/_masar__sources.yml¶

    As printed in the participant guide. The teaching point is that loaded_at_field: _ingested_at only works because Lab 1 wrote that column. Say it out loud: the governance control in Module 3 is paid for by the discipline in Module 1.

    1.3 models/staging/masar/stg_trips.sql — complete¶

    The participant version is the reference. The three graded behaviours:

    -- (1) BOTH timestamp formats parsed, then normalised ONCE to UTC
to_utc_timestamp(
    coalesce(
        to_timestamp(pickup_ts,  'yyyy-MM-dd HH:mm:ss'),
        to_timestamp(pickup_ts,  'dd/MM/yyyy HH:mm')
    ), 'Asia/Riyadh')             as pickup_ts,

-- (2) '' is missing, not a value
nullif(trim(dropoff_geohash), '') as dropoff_geohash,

-- (3) source duration is kept under a name that says it is unverified
cast(duration_min as double)      as reported_duration_min,

    1.4 models/marts/silver/silver_trips.sql — complete¶

    The participant version is the reference. The four graded properties, each with the line that delivers it:

    Property Delivered by
    Incremental + idempotent materialized='incremental', incremental_strategy='merge', unique_key='trip_id'
    Late-arrival safe where pickup_ts >= (select date_sub(max(pickup_ts), {{ var('lookback_days', 3) }}) from {{ this }}) — event time, parameterised
    Deduplicated correctly row_number() over (partition by trip_id order by _ingested_at desc, _batch_id desc) = 1
    Conformed status = 'completed', dropoff_ts > pickup_ts, fare_sar > 0, distance_km > 0; derived features computed once

    Note for the instructor on alias/schema. schema='silver' + alias='trips' is what makes the dbt model resolve to the canonical silver.trips from CONVENTIONS.md. Pairs who leave the default get silver.silver_trips, which breaks every later lab's table reference. Catch this at the min-20 checkpoint of 3b, not at the end.

    1.5 Tests¶

    _silver__models.yml as printed (12 tests total: 2 on trip_id, 2 on city, 1 on status, 2 on fare_sar, 2 on duration_min, 2 on driver_id, 1 on pickup_ts, 1 on rider_id) plus the custom assert_no_future_trips.sql. Reference run: PASS=12 WARN=0 ERROR=0 SKIP=0.

    1.6 The backfill drill — reference commands and outcomes¶

    python -m masar.ingest.land_bronze --feed trips --date 2026-06-01 \
       --source data/fixtures/late_trips/trips_late_2026-06-02.csv
cd dbt/masar && dbt run --select silver_trips
    Run Delta operationMetrics Meaning
    before drill WRITE numOutputRows -> 42038 full build
    no new data MERGE inserted -> 0, updated -> 0 idempotent
    after late fixture MERGE inserted -> 1, updated -> 0 late trip caught once
    repeat of the same backfill MERGE inserted -> 0, updated -> 0 backfills are safe to re-run

    The counter-experiment. Keep a branch sim-naive-filter with the where to_date(pickup_ts) = current_date() variant pre-baked so pairs can switch in 30 seconds rather than editing and rebuilding. Result: the late trip is absent, count stays 42,038.

    2. Teaching moments — what to say and exactly when¶

    Lab 3a (35 min)¶

    When Trigger The moment Say this
    Min 3 dbt debug green ELT in one sentence "dbt is not moving any data. It is issuing SQL to the engine that already holds the data. That is the L-then-T in ELT, and it is only affordable because of the cost model you built yesterday."
    Min 10 Freshness SLA tightened to 1 minute and WARNs A guard you never fired is not a guard "You have now seen the check fail. Every alert you add should be tested by making it fire once, deliberately, on the day you add it."
    Min 12 — What freshness misses "Freshness catches a stopped job. It does not catch a job that runs on time and lands an empty file. Which check catches that?" (volume — Module 6)
    Min 25 Both timestamp formats parsed Isolate quirks at the boundary "That coalesce exists in exactly one model. When the source adds a third format, you edit one file. Put it in the mart instead and you edit ten."
    Min 30 A pair reports non-zero unparseable rows Never mask a parse failure "A blanket cast turns 1,928 timestamps into nulls and tells you nothing. Find the format, add the branch."

    Lab 3b (55 min)¶

    When Trigger The moment Say this
    Min 10 Someone writes DISTINCT for dedup DISTINCT is the wrong tool "Your second batch corrected a fare. The rows now differ. DISTINCT keeps both — and your unique test fails. You do not want distinct rows, you want the latest row per key."
    Min 20 First dbt run --select silver_trips completes Check the alias Walk the room: spark.table("silver.trips").count() must work. If it is silver.silver_trips, fix it now
    Min 30 Second run shows updated -> 0 Idempotency, visible "You just ran the transformation twice and the table did not change. That is why your orchestrator is allowed to retry, why a backfill is safe, and why disaster recovery is a re-run instead of a project."
    Min 35 A relationships test fails Never delete a failing test "The test is correct and the data is wrong. You have three options: quarantine, admit-with-nulls, or fix the source. Deleting the test is not one of them."
    Min 42 — the headline moment Late trip merged, inserted -> 1 The whole module in one number Stop the room. "This trip ended yesterday and arrived today. With WHERE trip_date = current_date() it is invisible forever — a 2% silent undercount that underpays drivers and skews your model's labels. With a lookback window and a merge on the key, it is counted exactly once. Three lines of SQL. That is Module 3."
    Min 46 Counter-experiment run See the bug, not just the fix Require every pair to see the missing trip. The fix means nothing without the failure
    Min 52 dbt docs lineage graph on screen Docs generated from the work itself "This graph cannot drift from the pipeline, because it is the pipeline. That is the audit artefact PDPL governance needs, and you got it for free."

    Rehearse: the min-42 reveal, and have sim-naive-filter pre-baked so the counter-experiment costs 2 minutes, not 10.

    3. Common wrong answers and how to redirect¶

    What you will see Why it happens Redirect
    Lookback on _ingested_at Sounds like "process what just arrived" Draw the two timelines. Ask: "Which axis does the incentive payment use?" (event time)
    where pickup_ts >= current_date() - 3 Absolute rather than relative to the table Works today, breaks on any backfill or after an outage. Anchor on max(pickup_ts) from {{ this }}
    No lookback at all, just is_incremental() with a _ingested_at > max() filter Copied from a generic dbt example Run the drill; the late trip is caught (it arrived late) but a correction to an older trip is not. Both matter
    DISTINCT or group by trip_id for dedup Familiar SQL reflex See min-10 teaching moment
    Dedup applied after the join Order-of-operations slip Symptom: Cannot perform MERGE as multiple source rows matched. Fix the CTE order
    inner join drivers to make relationships pass Wants a green test "You just deleted 14 real trips and their revenue. Show me where that is recorded."
    Deleting a failing test Time pressure Non-negotiable. Mark it down; it is the difference between a pipeline and a hobby
    Casting/renaming in the mart Skipped staging discipline Set the stretch-goal rename drill as a live challenge: "Rename fare_sar upstream. Time how long your version takes to fix."
    to_timestamp(pickup_ts) with no format Assumes Spark guesses It does — for one format. Run the null count
    Timezone applied twice (to_utc_timestamp in staging and in the mart) Copy-paste Symptom: times 6 hours off. Normalise once, present with from_utc_timestamp
    status IN ('completed','cancelled_rider') in silver "We might need cancellations" Legitimate design question — but then the accepted_values test and the silver contract must change together, and every downstream count changes. Make them state the contract
    Model named silver_trips with default schema Missed the alias/schema config Fix immediately; Labs 4, 6, 7, 8 all reference silver.trips

    6. Grading notes¶

    Lab 3 is the heaviest formative lab and it is a direct capstone component (requirement 3). Grade it against the contract, not the SQL style.

    Criterion Weight Full marks Partial Zero
    Sources + freshness 10% 3 sources declared with SLAs; freshness run; WARN demonstrated Declared, never run Missing
    Staging discipline 15% Views, 1:1 with source, no joins, both timestamp formats parsed, UTC normalised once, 0 unparseable Casting present but a quirk unhandled Joins/business logic in staging
    Incremental config 15% incremental + merge + unique_key='trip_id' + file_format='delta', resolving to silver.trips Correct strategy, wrong table name Append strategy or table materialisation
    Lookback window 15% On event time, parameterised, anchored on max(pickup_ts) from {{ this }} Present but on ingest time or hard-coded Absent
    Dedup correctness 10% Latest row per key via row_number(); count(*) == count(distinct trip_id) DISTINCT used but test passes by luck Duplicates present
    Tests 15% ≥ 6 declared + 1 custom, all passing, no test deleted to go green 6 tests, one failing and documented Tests deleted/weakened to pass
    Backfill drill 15% Late trip merged exactly once and repeat run is a no-op, both evidenced from operationMetrics Late trip merged, repeat not shown Not attempted
    Notes + benchmark + commit 5% Counter-experiment recorded with both counts; benchmark filled; conventional commit Partial Missing

    Red flags - A green dbt test with fewer tests than the model started with → a test was deleted. Check git diff on the YAML. This is the single most important integrity signal in this lab. - silver.trips row count equal to bronze (96,400) → dedup absent; every downstream count in Labs 4, 7 and 8 will be double. - Identical LAB3_NOTES.md backfill metrics across pairs → the operationMetrics timestamps and version numbers differ per run; identical blocks mean copied output.

    Fast-forward path. git checkout lab3-solution && cd dbt/masar && dbt deps && dbt run && dbt test. Record who used it; a pair that fast-forwards Lab 3 will struggle in Lab 4's MERGE work, so pair them with a strong finisher on Day 3.

    Carry into Module 4. Ask three pairs for their second-run operationMetrics and put them on the board. Open M4 with: "dbt just did a MERGE for you. Today you find out what a MERGE actually is, why it is atomic, and what the log recorded while it happened."
