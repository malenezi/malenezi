    Land the Masar Raw Feeds into Bronze¶

    Field Value
    Lab LAB-01 · Module 1 · Day 1 Hour 3 · 50 minutes · pairs
    Tags participants start at lab1-start; reference at lab1-solution
    Room setup Projector on the _delta_log/profiling terminal; one floater per 8 participants for the first hour (JAVA_HOME is the top Day-1 failure)
    Pre-flight Run the reference solution on a clean clone the morning of delivery; confirm trips_2026-06-01.csv = 48,200 data rows

    Scale note. Figures quoted in this document assume the full-scale generator run (--scale 1.0); the shipped sample is --scale 0.15 — 7,230 trips/day over 5 days (36,150 trips), 873,763 GPS pings, 3,450 drivers, 3,864 vehicles, 48 zones. Grains, ratios and file-count reductions hold at either scale; absolute row counts do not.

    1.1 src/masar/spark.py (shipped, not written by participants)¶

    """One place to build the Spark session with Delta Lake enabled."""
from pyspark.sql import SparkSession


def get_spark(app_name: str = "masar-lakehouse") -> SparkSession:
    return (
        SparkSession.builder
        .appName(app_name)
        .config("spark.sql.extensions",
                "io.delta.sql.DeltaSparkSessionExtension")
        .config("spark.sql.catalog.spark_catalog",
                "org.apache.spark.sql.delta.catalog.DeltaCatalog")
        .config("spark.sql.warehouse.dir", "./lakehouse")
        .config("spark.sql.shuffle.partitions", "8")
        .config("spark.databricks.delta.retentionDurationCheck.enabled", "true")
        .enableHiveSupport()
        .getOrCreate()
    )

    1.2 src/masar/ingest/land_bronze.py — complete¶

    """Land raw Masar source files into the bronze zone.

Bronze rules enforced here:
  - append-only (never overwrite history)
  - keep data AS-RECEIVED (no cleaning, no typing beyond the source)
  - attach ingestion lineage: when, from which file, and under which batch
"""
from __future__ import annotations

import argparse
import uuid
from datetime import datetime, timezone

from pyspark.sql import DataFrame, functions as F

from masar.spark import get_spark

BRONZE = "./lakehouse/bronze"
RAW = "./data/raw"


def _batch_id(feed: str, business_date: str) -> str:
    stamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
    return f"{feed}_{business_date}_{stamp}_{uuid.uuid4().hex[:8]}"


def _with_lineage(df: DataFrame, batch_id: str) -> DataFrame:
    return (
        df.withColumn("_ingested_at", F.current_timestamp())
          .withColumn("_source_file", F.input_file_name())
          .withColumn("_batch_id", F.lit(batch_id))
    )


def _append(df: DataFrame, table: str, path: str) -> int:
    spark = get_spark()
    spark.sql("CREATE DATABASE IF NOT EXISTS bronze")
    n = df.count()
    (df.write
        .format("delta")
        .mode("append")
        .option("mergeSchema", "false")
        .option("path", path)
        .saveAsTable(table))
    total = spark.read.format("delta").load(path).count()
    print(f"Landed {n:,} rows -> {path}  (append, total now {total:,})")
    return total


def land_trips(business_date: str, source: str | None = None) -> int:
    spark = get_spark("land-trips")
    raw = (spark.read
           .option("header", True)
           .option("mode", "PERMISSIVE")
           .option("inferSchema", False)
           .csv(source or f"{RAW}/trips_{business_date}.csv"))
    return _append(_with_lineage(raw, _batch_id("trips", business_date)),
                   "bronze.trips", f"{BRONZE}/trips")


def land_gps(business_date: str, source: str | None = None) -> int:
    spark = get_spark("land-gps")
    raw = spark.read.json(source or f"{RAW}/gps/gps_{business_date}.ndjson")
    return _append(_with_lineage(raw, _batch_id("gps", business_date)),
                   "bronze.gps_events", f"{BRONZE}/gps_events")


def land_drivers(source: str | None = None) -> int:
    spark = get_spark("land-drivers")
    today = datetime.now(timezone.utc).strftime("%Y-%m-%d")
    raw = (spark.read
           .option("header", True)
           .option("mode", "PERMISSIVE")
           .option("inferSchema", False)
           .csv(source or f"{RAW}/drivers.csv"))
    return _append(_with_lineage(raw, _batch_id("drivers", today)),
                   "bronze.drivers", f"{BRONZE}/drivers")


def main() -> None:
    p = argparse.ArgumentParser(description="Land a Masar raw feed into bronze")
    p.add_argument("--feed", required=True, choices=["trips", "gps", "drivers", "all"])
    p.add_argument("--date", default="2026-06-01")
    p.add_argument("--source", default=None, help="override the source path (fixtures)")
    a = p.parse_args()
    if a.feed in ("trips", "all"):
        land_trips(a.date, a.source)
    if a.feed in ("gps", "all"):
        land_gps(a.date, a.source)
    if a.feed in ("drivers", "all"):
        land_drivers(a.source)


if __name__ == "__main__":
    main()

    1.3 src/masar/ingest/profile_bronze.py — complete¶

    The participant version in the lab guide is the reference. The only addition worth showing on the projector is the one-line summary the instructor uses to check a pair's work quickly:

    def summary(table_path: str, key: str) -> None:
    spark = get_spark("profile-summary")
    df = spark.read.format("delta").load(table_path)
    n = df.count()
    dupes = df.groupBy(key).count().filter("count > 1").count()
    lineage_ok = {"_ingested_at", "_source_file", "_batch_id"} <= set(df.columns)
    batches = df.select("_batch_id").distinct().count()
    print(f"rows={n:,} dup_{key}_groups={dupes:,} batches={batches} lineage_ok={lineage_ok}")

    2. Teaching moments — what to say and exactly when¶

    When Trigger The moment Say this
    Min 5, after Task 1 Pairs have grepped the raw files The defects are the curriculum "Everything you just found — the 3.1% empty geohash, the two date formats, the negative durations — is in this file on purpose. Write them down. You will fix each one at a specific layer, and I will ask you which layer."
    Min 12, during Task 2 Someone asks "shouldn't we clean this first?" Bronze is a ledger, not a model "Cleaning at landing means the only copy you have is the cleaned one. When your cleaning rule turns out to be wrong in week six, what do you re-run it against?"
    Min 14 A pair sets inferSchema=True Inference is silent data loss Run it live: inference nulls the 2% dd/MM/yyyy timestamps. "Your pipeline just deleted 1,928 timestamps and told you nothing."
    Min 22, Task 3 — the headline moment Second landing completes, totals hit 96,400 Bronze should allow duplication Stop the room. "Who thinks 96,400 rows for a 48,200-trip day is a bug?" Take a show of hands, then: "It is correct. Bronze records what arrived. Silver decides what is true — and it can, because _batch_id tells it which arrival is later. If we had overwritten, the duplication would be invisible and the history gone."
    Min 30, Task 4 Null-rate table on screen A null rate is a downstream design decision "3.1% missing dropoff_geohash. Who owns what happens next — engineering, data science, or operations? Your answer determines which layer encodes the rule."
    Min 38, Task 5 GPS file counts on screen File count is a cost, not an aesthetic "Remember this number. Module 2 will price it and Module 4 will fix it. Object storage bills you for listing, not just for bytes."
    Min 45, wrap — The unifying question "What happens to Masar's AI system if the landing zone fails? Not a crash. A model retrained on a table you can no longer rebuild."

    Rehearse: the inferSchema=True demo (30 seconds) and the 96,400 reveal. Those two carry the hour.

    3. Common wrong answers and how to redirect¶

    What you will see Why it happens Redirect (do not just correct)
    mode("overwrite") in land_trips Habit from ETL/warehouse work; "I don't want duplicates" Ask: "Run it twice. Now show me yesterday's data." Let them discover it is gone. Then: "Which layer removes duplicates, and why is that better?"
    .dropDuplicates("trip_id") at landing Conflating bronze with silver "You just made a business decision — which copy wins? — inside an ingestion job, with no test and no record. Move it to silver where it is reviewable"
    inferSchema=True Convenience Live demo (above). Then: "Bronze's job is to be a faithful copy. Typing is a transformation and transformations belong where they can fail loudly"
    mode("DROPMALFORMED") Sounds hygienic "How many rows did you just drop? You cannot answer, because they are gone. PERMISSIVE keeps them and lets you count them"
    Lineage columns added after a groupBy/distinct Copy-paste ordering Show _source_file is null: input_file_name() is only meaningful on a direct file scan
    "Swamp risks" listed as vague adjectives ("data is messy") Not enough rigour Require the evidence line: risk + the number that proves it + the layer that fixes it. Reject anything without all three
    Partitioning bronze by trip_id "for fast lookups" Warehouse index intuition Let them do it in the stretch goal and measure. The file count argues better than you can
    Committing lakehouse/ to git No .gitignore awareness Catch it early — it is a capstone hand-in failure. git rm -r --cached lakehouse
    Landing GPS with spark.read.json(..., multiLine=True) Copied from a JSON-array example Works but reads the whole file as one document — show the partition count collapse to 1 and the memory spike

    6. Grading notes¶

    Lab 1 is formative (completion-graded within the "Labs completion" 60% band), but it feeds two capstone-graded artefacts, so mark it honestly.

    Criterion Weight Full marks Partial Zero
    Bronze tables exist as Delta at the canonical paths and names 20% All three, correct names (bronze.trips, bronze.gps_events, bronze.drivers) and paths Two of three, or path/name drift Non-Delta output, or wrong zone
    Append-only proven 25% 96,400 rows and two distinct _batch_id values Append used but the re-run not demonstrated mode("overwrite") anywhere
    Lineage metadata 15% All three columns, non-null, on all three tables _batch_id missing, or _source_file null No lineage
    As-received discipline 15% No casting/cleaning/dedup; CSV columns still STRING; GPS payload still nested Minor typing at landing Cleaning or filtering at landing
    LAB1_NOTES.md swamp risks 15% ≥ 3 risks, each with an evidence number and the owning layer ≥ 3 risks without evidence or layer < 3, or vague
    Benchmark table + commit 10% Filled from own run; conventional commit message; lakehouse/ not committed Partial Missing

    Red flags to act on immediately - lakehouse/ staged in git → fix now; it fails the capstone repository hand-in. - Identical LAB1_NOTES.md content across pairs → note it; the academic-integrity check on Day 5 compares benchmark and quarantine artefacts across repositories. - A pair whose bronze.trips has 48,200 rows at min 30 → they overwrote. Do not let them proceed to Lab 3 without fixing it; the whole silver dedup lesson depends on having two batches.

    Fast-forward path. A pair that cannot finish should git checkout lab1-solution && python -m masar.ingest.land_bronze --feed all --date 2026-06-01 twice for trips, then continue. Record who used it — repeated fast-forwarding by Day 3 is the signal to reassign pairs.

    What to carry into Module 2. Collect the GPS numFiles and average file size from three pairs and put them on the board before the M2 lecture. Opening compute–storage economics with the room's own numbers lands better than the slide.
