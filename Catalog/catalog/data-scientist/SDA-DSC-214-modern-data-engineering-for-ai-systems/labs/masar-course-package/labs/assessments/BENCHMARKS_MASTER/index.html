    BENCHMARKS MASTER — SDA-DSC-214¶

    Every module's benchmark table in one instructor reference. Modern Data Engineering for AI Systems · SDAIA Academy

    What this is for. During labs and capstone grading, a participant shows you a number. This document tells you, at a glance, whether that number is in range, how it was supposed to be measured, and what the reference run produced. Use it to spot the two failure modes that matter: a number that is impossible (fabricated or measured wrong) and a number that is plausible but wrong (measured on the wrong thing).

    The reference column is a MacBook Pro M2, 16 GB, Spark 3.5.1 local[8], delta-spark 3.2.0, single-broker Kafka, spark.sql.shuffle.partitions=8. Absolute timings on other hardware will differ, sometimes by 3×. Ratios and counts are the deliverable; timings are context. Say this to the room on Day 1 and repeat it on Day 5.

    Scale note. Figures quoted in this document assume the full-scale generator run (--scale 1.0); the shipped sample is --scale 0.15 — 7,230 trips/day over 5 days (36,150 trips), 873,763 GPS pings, 3,450 drivers, 3,864 vehicles, 48 zones. Grains, ratios and file-count reductions hold at either scale; absolute row counts do not.

    0. Reading a participant's number in ten seconds¶

    Ask If the answer is Then
    Is it a count or a ratio? count or ratio It must land in the range below. Hardware is no excuse
    absolute timing Check the ratio between their before and after instead
    Was the JVM warm? first run of the session Landing throughput is dominated by 6–10 s of JVM and Delta-jar startup. Ask for the second run
    Is the hardware stated in BENCHMARKS.md? no The number is unsourced. Criterion 1/2 evidence, not a pass/fail
    Does it match another participant's exactly? yes, on a timing Integrity signal A7. Ratios may legitimately match; absolute timings on different laptops do not

    The three numbers that are never negotiable, whatever the hardware:

    Number Must be Why
    Pipeline-introduced streaming duplicates after kill/restart 0 This is LO5's entire claim
    silver.trips rows − distinct trip_id 0 The grain is the contract every gold table rests on
    gold.eta_features column count 13 The CONVENTIONS contract; more or fewer is a contract breach

    numFiles = 214 caveat — say this aloud. It assumes the participant ran Lab 3's backfill drill and this lab's MERGE cycles. A pair who fast-forwarded may start at 12 files and see a much smaller reduction. That is not a failure.     Appendix B — Numbers a participant should never report¶

    Use this as a fabrication and mis-measurement screen.

    Reported Why it is wrong
    Pipeline duplicates > 0 after kill/restart, described as "expected" Confusing the 0.4% seeded source defect with a pipeline fault
    Pipeline duplicates = 0 without a kill/restart having been performed The claim has no evidence; the number is a default, not a measurement
    numFiles reduction ≥ 10× on a table built in a single write Nothing was fragmented; the ratio was copied from the lab guide
    Gigabytes reclaimed by VACUUM on lab day at RETAIN 168 HOURS Tombstoned files are inside the retention window; either the retention was shortened or the figure is invented
    Byte reduction exactly equal to the column reduction (e.g. both 89%) Estimated from column count rather than measured from the plan
    rel_diff "close to zero" It is exactly zero when both paths descend from the same silver; "close" means a filter differs
    Post-fix R² still above 0.85 The leak was not fixed, whatever the classification table says
    Landing throughput ≥ 200k rows/s on a cold first run Measured a warm-cache re-read, or reported the target rather than the result
    Identical absolute timings to another participant Integrity signal A7 — ratios may match, laptop timings do not
    Late-data drops = 0 with the late-ping fixture loaded Either the fixture was not loaded or the watermark is too generous to be doing anything
