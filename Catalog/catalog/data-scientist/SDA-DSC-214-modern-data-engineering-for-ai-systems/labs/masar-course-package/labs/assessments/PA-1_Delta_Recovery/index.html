    PA-1 — Delta Recovery: A Vacuumed Table and a Non-Idempotent Merge¶

    Field Value
    Assessment ID PA-1
    Module M4 — Delta Lake and ACID Transactions
    Day / Hour Day 3, end of Hour 5 (immediately after the Lab-4 wrap)
    Duration 30 minutes, individual, open-repository / closed-collaboration
    LO mapping LO4 (primary) · LO6 (audit and retention governance) · LO3 (idempotent upsert)
    Weight Half of the 20% practical-assessment band (PA-1 + PA-2 + PA-3 → 20%)
    Sandbox ./lakehouse/_assessments/pa1/trips — a copy of silver.trips with the identical schema and grain. The participant's own silver.trips is never touched.
    Marking Diagnosis 40% · Fixes 40% · Verification evidence 20%

    The course question, applied: "What happens to Masar's AI system if THIS part of the data platform fails?" Here it fails twice at once: the platform can no longer prove what it contained yesterday, and every corrections run silently multiplies trips. The demand mart inflates, the ETA training set gains phantom rows, and the audit trail that would have shown you both is gone.

    Scale note. Figures quoted in this document assume the full-scale generator run (--scale 1.0); the shipped sample is --scale 0.15 — 7,230 trips/day over 5 days (36,150 trips), 873,763 GPS pings, 3,450 drivers, 3,864 vehicles, 48 zones. Grains, ratios and file-count reductions hold at either scale; absolute row counts do not.

    1. Instructor setup¶

    Run this before the session. It takes ~90 seconds and produces the broken starting state for every participant. Distribute the resulting directory, or have each participant run make pa1-setup (the target wraps this script).

    # scripts/assessments/pa1_setup.py
"""PA-1 setup: build a Delta table with (a) destroyed time travel and
(b) a non-idempotent corrections job.

Run:  python -m scripts.assessments.pa1_setup
Idempotent: the sandbox is deleted and rebuilt on every run.
"""
from __future__ import annotations

import shutil
from pathlib import Path

from delta.tables import DeltaTable
from pyspark.sql import functions as F

from masar.spark import get_spark

SOURCE  = "./lakehouse/silver/trips"                    # the cohort's real silver table
SANDBOX = "./lakehouse/_assessments/pa1/trips"
CORRECT = "data/fixtures/corrections/trips_corrections_2026-06-03.csv"


def main() -> None:
    spark = get_spark("pa1-setup")
    shutil.rmtree(Path(SANDBOX).parent, ignore_errors=True)

    # ---- v0: a clean copy of silver.trips (schema and grain identical) -----
    src = spark.read.format("delta").load(SOURCE)
    src.write.format("delta").mode("overwrite").save(SANDBOX)
    spark.sql(f"ALTER TABLE delta.`{SANDBOX}` "
              f"ADD CONSTRAINT positive_fare CHECK (fare_sar > 0)")

    tgt = DeltaTable.forPath(spark, SANDBOX)
    schema = spark.read.format("delta").load(SANDBOX).schema
    corr = spark.read.option("header", True).schema(schema).csv(CORRECT)

    # ---- v1: a legitimate, idempotent correction (so history is meaningful)
    (tgt.alias("t").merge(corr.alias("s"), "t.trip_id = s.trip_id")
        .whenMatchedUpdateAll().execute())

    # ---- v2, v3: the NON-IDEMPOTENT job, run twice ------------------------
    # The match condition includes a per-run column, so nothing ever matches
    # and every run falls through to whenNotMatchedInsertAll.
    for _ in range(2):
        stamped = corr.withColumn("_ingested_at", F.current_timestamp())
        (tgt.alias("t")
            .merge(stamped.alias("s"),
                   "t.trip_id = s.trip_id AND t._ingested_at = s._ingested_at")
            .whenMatchedUpdateAll()
            .whenNotMatchedInsertAll()
            .execute())

    # ---- v4: time travel destroyed ----------------------------------------
    spark.conf.set("spark.databricks.delta.retentionDurationCheck.enabled", "false")
    spark.sql(f"VACUUM delta.`{SANDBOX}` RETAIN 0 HOURS")
    spark.conf.set("spark.databricks.delta.retentionDurationCheck.enabled", "true")

    n = spark.read.format("delta").load(SANDBOX).count()
    d = spark.read.format("delta").load(SANDBOX).select("trip_id").distinct().count()
    print(f"[pa1-setup] rows={n:,} distinct trip_id={d:,} (expect {n-d:,} duplicate rows)")
    print(f"[pa1-setup] sandbox ready at {SANDBOX}")


if __name__ == "__main__":
    main()

"""Apply the daily corrections file to the PA-1 trips table."""
from __future__ import annotations

import argparse

from delta.tables import DeltaTable
from pyspark.sql import functions as F

from masar.spark import get_spark

TABLE = "./lakehouse/_assessments/pa1/trips"


def apply_corrections(path: str) -> None:
    spark = get_spark("pa1-corrections")
    schema = spark.read.format("delta").load(TABLE).schema

                 .withColumn("_ingested_at", F.current_timestamp()))

        .merge(corr.alias("s"),
               "t.trip_id = s.trip_id AND t._ingested_at = s._ingested_at")
        .whenMatchedUpdateAll()
        .whenNotMatchedInsertAll()

def maintain() -> None:
    """Nightly maintenance."""
    spark = get_spark("pa1-maintenance")
    spark.conf.set("spark.databricks.delta.retentionDurationCheck.enabled", "false")
    spark.sql(f"OPTIMIZE delta.`{TABLE}` ZORDER BY (city, pickup_ts)")

    print("maintenance done")

    2. Participant brief (hand this page out)¶

    PA-1 — Delta Recovery · 30 minutes · individual

    Masar's overnight corrections job has been running for four days. This morning the demand mart shows more completed trips than the platform ingested, and when Compliance asked what silver.trips contained before Tuesday's corrections, the query failed.

    You have been handed the table and the job that maintains it:

    • Table: ./lakehouse/_assessments/pa1/trips (a copy of silver.trips, same schema, same intended grain: one row per trip_id)
    • Job: src/masar/delta/apply_corrections_pa1.py
    • Corrections fixture: data/fixtures/corrections/trips_corrections_2026-06-03.csv (5 rows)

    Your task, in order:

    1. Diagnose. Find every defect in the table state and in the job. For each, state the mechanism — not "the merge is broken" but why the merge condition never matches — and the consumer-visible consequence in Masar terms (which mart, which model, which number).
    2. Fix. Repair the job so that (a) applying the corrections twice leaves the table identical, and (b) maintenance is safe to schedule. Restore the table to its correct grain. You may not rebuild the table from silver.trips — the point is recovery, and in production the source would be gone.
    3. Prove it. Produce evidence a reviewer can check without re-running anything: before/after counts, both operationMetrics blocks, the DESCRIBE HISTORY timeline, and a statement of what time travel can and cannot now do.

    Constraints - Do not disable spark.databricks.delta.retentionDurationCheck. - Do not delete _delta_log. - Keep the schema unchanged; the grain is one row per trip_id. - Everything you write must be committed on branch pa1/<your-name>.

    Deliverable artefacts (all three required):

    Artefact Content
    PA1_DIAGNOSIS.md One numbered entry per defect: symptom → mechanism → consumer consequence → evidence line
    src/masar/delta/apply_corrections_pa1.py The repaired job (both apply_corrections and maintain)
    PA1_EVIDENCE.md Command transcripts proving idempotency, the restored grain, and the retention decision, with a one-paragraph statement of what history was permanently lost and what that costs

    Time budget suggestion: 8 min diagnose · 12 min fix · 7 min evidence · 3 min commit.

    3. Marking scheme¶

    Total 100. Pass ≥ 70 for badge contribution; the PA band is averaged with PA-2 and PA-3.

    3a. Diagnosis — 40 marks¶

    Sub-criterion Marks What earns it
    D1. Non-idempotent MERGE identified with the mechanism 15 Names _ingested_at in the match condition, explains that it is stamped per run so WHEN MATCHED can never fire, and that every run therefore takes whenNotMatchedInsertAll
    D2. RETAIN 0 HOURS identified with both consequences 12 (i) time travel destroyed — prior versions unreadable, audit unanswerable; (ii) files can be deleted from under a concurrent reader or streaming query. Both needed for full marks
    D3. Grain violation quantified 8 States 42,048 rows vs 42,038 distinct trip_id, identifies the 10 rows as 5 corrections × 2 runs, and names the affected trip_ids
    D4. Consumer consequence in Masar terms 5 Connects the duplicates to a named downstream: gold.zone_hourly_demand over-counts those zone-hours; gold.eta_features gains duplicate training rows; the BI star stops reconciling with the demand mart

    4. Model answer¶

    4a. PA1_DIAGNOSIS.md¶

    Defect 1 — the corrections MERGE is not idempotent. Symptom: DESCRIBE HISTORY shows v2 and v3 both reporting numTargetRowsInserted -> 5, numTargetRowsUpdated -> 0, for a corrections file containing 5 trip_ids that already exist in the table. Mechanism: the match condition is t.trip_id = s.trip_id AND t._ingested_at = s._ingested_at, and _ingested_at is stamped with F.current_timestamp() on the source at read time. The target's _ingested_at is whatever the previous run wrote. The two can never be equal across runs, so whenMatched never fires and control falls through to whenNotMatchedInsertAll — the job appends a fresh copy of all 5 corrections every night. Consumer consequence: the table's grain (one row per trip_id) is broken, so gold.zone_hourly_demand over-counts the affected zone-hours, gold.driver_daily over-counts those drivers' trips and revenue, and gold.eta_features gains duplicated training rows for the same trip — which also corrupts a time-based train/test split. The BI star and the demand mart stop reconciling, which is the two-tier divergence symptom appearing inside a single platform. Evidence: rows=42,048 distinct_trip_id=42,038 — surplus 10 = 5 corrections × 2 runs.

    Defect 2 — VACUUM ... RETAIN 0 HOURS with the safety check disabled. Symptom: SELECT COUNT(*) ... VERSION AS OF 1 raises FileNotFoundException naming a Parquet file listed in the log. Mechanism: maintain() sets spark.databricks.delta.retentionDurationCheck.enabled = false and vacuums with zero retention, so every data file not referenced by the current snapshot is deleted immediately. The transaction log still describes versions 0–3, but their files are gone: the log is intact and unusable. Consequence A (governance): the audit question "what did this table contain before Tuesday's corrections?" is now unanswerable from this table. The pre-correction fare values existed only in v0–v1. Consequence B (availability): zero retention also deletes files a concurrently running reader or streaming query is about to open, failing a healthy job with the same exception. This is why Delta requires an explicit override. Evidence: v4 VACUUM END {numDeletedFiles -> 16} followed by the failing VERSION AS OF 1.

    Defect 3 — the table is currently out of contract. Symptom: 10 surplus rows; the 5 corrected trip_ids each appear three times (the original, plus one insert per non-idempotent run). Mechanism: a consequence of Defect 1, but it must be repaired separately — fixing the job stops the bleeding and does not clean the wound. Consequence: as Defect 1. Note that the surplus rows are not identical: they carry different _ingested_at values, so a naive DISTINCT will not collapse them. Evidence: 

    trip_id                copies  ingested_at_values
trp_20260601_004417    3       2026-06-19 19:07 / 2026-06-22 02:00 / 2026-06-23 02:00

    What I cannot determine from this table alone: whether any other corrections file was applied by the same job on earlier nights. The _batch_id and _source_file lineage columns on bronze.trips would answer it; that is where I would look next, and it is why bronze exists.

    4b. The repaired job¶

    # src/masar/delta/apply_corrections_pa1.py   (repaired)
from __future__ import annotations

import argparse

from delta.tables import DeltaTable
from pyspark.sql import functions as F

from masar.spark import get_spark

TABLE = "./lakehouse/_assessments/pa1/trips"
RETENTION_HOURS = 168          # 7 days. Justified in PA1_EVIDENCE.md.


def apply_corrections(path: str) -> None:
    """MERGE keyed on the BUSINESS key only. Re-running is a no-op."""
    spark = get_spark("pa1-corrections")
    schema = spark.read.format("delta").load(TABLE).schema
    corr = (spark.read.option("header", True).schema(schema).csv(path)
                 .withColumn("_ingested_at", F.current_timestamp()))

    # F2: the source must be one row per key, or whenMatchedUpdateAll is ambiguous.
    dupes = corr.groupBy("trip_id").count().filter("count > 1").count()
    if dupes:
        raise ValueError(f"{dupes} duplicate trip_id in {path}: MERGE would be ambiguous")

    target = DeltaTable.forPath(spark, TABLE)
    (target.alias("t")
        .merge(corr.alias("s"), "t.trip_id = s.trip_id")   # F1: business key only
        .whenMatchedUpdateAll()
        .whenNotMatchedInsertAll()
        .execute())

    m = (spark.sql(f"DESCRIBE HISTORY delta.`{TABLE}` LIMIT 1")
              .select("version", "operationMetrics").first())
    print(f"v{m['version']} MERGE updated={m['operationMetrics'].get('numTargetRowsUpdated')} "
          f"inserted={m['operationMetrics'].get('numTargetRowsInserted')}")


def restore_grain() -> None:
    """F3: repair the damage already done, in place. Keep the LATEST row per key.

    Rationale for 'latest': every surplus row is a re-insertion of the same
    correction, so all copies carry identical business values; the newest
    _ingested_at is the one whose lineage matches the most recent run. The
    rule is therefore lossless here, and it is stated before it is executed.
    """
    spark = get_spark("pa1-restore-grain")
    df = spark.read.format("delta").load(TABLE)
    surplus = df.count() - df.select("trip_id").distinct().count()
    print(f"[grain] surplus rows before: {surplus}")

    keep = (df.withColumn("_rn", F.row_number().over(
                __import__("pyspark.sql.window", fromlist=["Window"]).Window
                .partitionBy("trip_id").orderBy(F.col("_ingested_at").desc())))
              .filter("_rn = 1").drop("_rn"))

    # Atomic replacement: one commit, readers never see a partial table.
    keep.write.format("delta").mode("overwrite").option("overwriteSchema", "false").save(TABLE)

    df2 = spark.read.format("delta").load(TABLE)
    print(f"[grain] rows={df2.count():,} distinct trip_id={df2.select('trip_id').distinct().count():,}")


def maintain() -> None:
    """F4: safe, schedulable maintenance. The retention check stays ON."""
    spark = get_spark("pa1-maintenance")
    before = spark.sql(f"DESCRIBE DETAIL delta.`{TABLE}`").first()["numFiles"]
    spark.sql(f"OPTIMIZE delta.`{TABLE}` ZORDER BY (city, pickup_ts)")
    after = spark.sql(f"DESCRIBE DETAIL delta.`{TABLE}`").first()["numFiles"]
    print(f"[maintain] numFiles {before} -> {after}")

    spark.sql(f"VACUUM delta.`{TABLE}` RETAIN {RETENTION_HOURS} HOURS DRY RUN").show(5, False)
    spark.sql(f"VACUUM delta.`{TABLE}` RETAIN {RETENTION_HOURS} HOURS").show(truncate=False)


if __name__ == "__main__":
    p = argparse.ArgumentParser()
    p.add_argument("--corrections")
    p.add_argument("--restore-grain", action="store_true")
    p.add_argument("--maintain", action="store_true")
    a = p.parse_args()
    if a.restore_grain:
        restore_grain()
    if a.corrections:
        apply_corrections(a.corrections)
    if a.maintain:
        maintain()

    Marker's note on restore_grain. An overwrite here is correct and is not the "overwrite where a MERGE was needed" anti-pattern: the operation intentionally replaces the whole table with a de-duplicated projection of itself, in one atomic commit, and it is a one-off repair rather than a scheduled write. Accept an equivalent DeltaTable.delete on a computed surplus predicate, or a MERGE-based rewrite, provided the participant states why the rule is lossless. Reject any repair that reads from silver.trips.

    What was permanently lost, and what it costs. Versions 0–3 remain described in _delta_log but their data files were deleted by the RETAIN 0 HOURS vacuum, so the table can no longer answer "what were these five fares before Tuesday's correction?" That is exactly the question a fare dispute or a regulator's audit asks, and this table can no longer answer it. The platform is not entirely blind: bronze.trips is append-only and still holds the raw rows with _source_file and _batch_id, so the pre-correction values are re-derivable by replaying the silver transform against a bronze snapshot — slower, and it proves what the source said rather than what the table served, which is a weaker form of evidence. Time travel from v5 onward is intact and is the version floor for any future audit.

    Retention decision: RETAIN 168 HOURS. Three inputs. (a) Audit window: Masar's fare-dispute process runs to five working days, so the live table must serve seven days of prior versions. (b) PDPL: an honoured erasure must not leave personal data physically recoverable indefinitely; seven days bounds the gap between the DELETE commit and physical removal, and the erasure runbook schedules a VACUUM after that window rather than relying on the nightly job. (c) Storage: seven days of tombstoned files on this table is under 5 MB at lab scale and a few GB at production scale — cheap relative to both other constraints. What would change the number: a longer statutory dispute window pushes it up; a stricter erasure SLA pushes it down; neither justifies zero, because zero also breaks concurrent readers.
