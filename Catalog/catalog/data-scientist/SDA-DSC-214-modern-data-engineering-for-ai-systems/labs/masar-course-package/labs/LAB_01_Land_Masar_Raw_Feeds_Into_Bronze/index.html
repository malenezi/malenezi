    LAB 01 — Land the Masar Raw Feeds into Bronze¶

    Field Value
    Lab ID LAB-01
    Module M1 — Evolution of Data Architecture: Warehouse, Lake, Lakehouse
    Day / Hour Day 1, Hour 3
    Duration 50 minutes (20% theory / 80% lab), pairs
    Difficulty Foundational
    LO mapping LO1 (primary — medallion / Lakehouse layering), LO7 (contributes — first Mini-Lakehouse component), LO6 (touched — lineage metadata as governance)
    Prerequisites LAB-00 complete (make doctor = 0 fail); M1 lecture (warehouse vs lake vs Lakehouse, medallion, swamp smells)
    Checkpoint git tag lab1-start (solution: lab1-solution)
    Deliverable bronze.trips, bronze.gps_events, bronze.drivers as append-only Delta tables under lakehouse/bronze/, each carrying _ingested_at, _source_file, _batch_id; plus LAB1_NOTES.md with ≥ 3 named swamp risks and the filled benchmark table

    Scale note. Figures quoted in this document assume the full-scale generator run (--scale 1.0); the shipped sample is --scale 0.15 — 7,230 trips/day over 5 days (36,150 trips), 873,763 GPS pings, 3,450 drivers, 3,864 vehicles, 48 zones. Grains, ratios and file-count reductions hold at either scale; absolute row counts do not.

    Why this lab matters¶

    Masar's ETA model is retrained weekly from trip and GPS history; the operations dashboard reads the same lineage. If the landing zone fails — or worse, silently succeeds while losing history — the AI system does not crash, it degrades invisibly. A pipeline that overwrites bronze on every run cannot reprocess when a silver transformation is later found to be wrong, so a bug discovered in week six is unfixable for weeks one to five: the raw evidence is gone. A landing zone with no _source_file cannot answer the regulator's question "which file produced this row?", and a landing zone with no profiling lets a 3.1% null dropoff_geohash reach the feature table as a plausible-looking zero. This lab builds the layer that makes every later correction possible, and it deliberately ships with the swamp smells you will spend Days 2–4 cleaning up.

    Task 2 — Implement land_bronze.py (10 min)¶

    Open src/masar/ingest/land_bronze.py. The starter has the docstring and stubs; fill them in. Bronze rules: append-only, as-received (no casting, no cleaning, no dropping), plus lineage metadata.

    # src/masar/ingest/land_bronze.py
"""Land raw Masar source files into the bronze zone.

Bronze rules enforced here:
  - append-only (never overwrite history)
  - keep data AS-RECEIVED (no cleaning, no typing beyond the source)
  - attach ingestion lineage: when, from which file, and under which batch
"""
from __future__ import annotations

import argparse
import uuid
from datetime import datetime, timezone

from pyspark.sql import DataFrame, functions as F

from masar.spark import get_spark

BRONZE = "./lakehouse/bronze"
RAW = "./data/raw"


def _batch_id(feed: str, business_date: str) -> str:
    """Deterministic-prefix, unique-suffix batch id: traceable AND collision-free."""
    stamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
    return f"{feed}_{business_date}_{stamp}_{uuid.uuid4().hex[:8]}"


def _with_lineage(df: DataFrame, batch_id: str) -> DataFrame:
    """Every bronze table carries the same three lineage columns (CONVENTIONS.md)."""
    return (
        df.withColumn("_ingested_at", F.current_timestamp())
          .withColumn("_source_file", F.input_file_name())
          .withColumn("_batch_id", F.lit(batch_id))
    )


def _append(df: DataFrame, table: str, path: str) -> int:
    """Append-only write. Registers the table in the catalog at the canonical path."""
    spark = get_spark()
    spark.sql("CREATE DATABASE IF NOT EXISTS bronze")
    n = df.count()
    (df.write
        .format("delta")
        .mode("append")               # NEVER overwrite: bronze is an immutable ledger
        .option("mergeSchema", "false")
        .option("path", path)
        .saveAsTable(table))
    total = spark.read.format("delta").load(path).count()
    print(f"Landed {n:,} rows -> {path}  (append, total now {total:,})")
    return total


def land_trips(business_date: str) -> int:
    spark = get_spark("land-trips")
    batch_id = _batch_id("trips", business_date)
    raw = (
        spark.read
        .option("header", True)
        .option("mode", "PERMISSIVE")      # keep malformed rows, do NOT drop them
        .option("inferSchema", False)      # everything lands as STRING: as-received
        .csv(f"{RAW}/trips_{business_date}.csv")
    )
    return _append(_with_lineage(raw, batch_id), "bronze.trips", f"{BRONZE}/trips")


def land_gps(business_date: str) -> int:
    """GPS pings arrive as newline-delimited JSON with a nested `payload` struct."""
    spark = get_spark("land-gps")
    batch_id = _batch_id("gps", business_date)
    raw = spark.read.json(f"{RAW}/gps/gps_{business_date}.ndjson")   # schema-on-read
    return _append(_with_lineage(raw, batch_id),
                   "bronze.gps_events", f"{BRONZE}/gps_events")


def land_drivers() -> int:
    spark = get_spark("land-drivers")
    batch_id = _batch_id("drivers", datetime.now(timezone.utc).strftime("%Y-%m-%d"))
    raw = (
        spark.read
        .option("header", True)
        .option("mode", "PERMISSIVE")
        .option("inferSchema", False)      # hire_date has MIXED formats: keep as string
        .csv(f"{RAW}/drivers.csv")
    )
    return _append(_with_lineage(raw, batch_id), "bronze.drivers", f"{BRONZE}/drivers")


def main() -> None:
    p = argparse.ArgumentParser(description="Land a Masar raw feed into bronze")
    p.add_argument("--feed", required=True, choices=["trips", "gps", "drivers", "all"])
    p.add_argument("--date", default="2026-06-01", help="business date YYYY-MM-DD")
    args = p.parse_args()

    if args.feed in ("trips", "all"):
        land_trips(args.date)
    if args.feed in ("gps", "all"):
        land_gps(args.date)
    if args.feed in ("drivers", "all"):
        land_drivers()


if __name__ == "__main__":
    main()

    The session builder is already written for you — read it, do not re-create Spark ad hoc:

    # src/masar/spark.py
"""One place to build the Spark session with Delta Lake enabled.

Every lab imports get_spark() — never reconfigure Spark ad hoc in a notebook.
"""
from pyspark.sql import SparkSession


def get_spark(app_name: str = "masar-lakehouse") -> SparkSession:
    """Spark 3.5 + Delta Lake 3.2 session for the Masar Lakehouse.

    Storage and compute are separate even locally: data lives under
    ./lakehouse (a stand-in for object storage s3://masar-lakehouse),
    compute is this JVM. enableHiveSupport() gives us a persistent
    catalog so `bronze.trips` means the same thing in every process
    (and to dbt in Lab 3).
    """
    return (
        SparkSession.builder
        .appName(app_name)
        .config("spark.sql.extensions",
                "io.delta.sql.DeltaSparkSessionExtension")
        .config("spark.sql.catalog.spark_catalog",
                "org.apache.spark.sql.delta.catalog.DeltaCatalog")
        .config("spark.sql.warehouse.dir", "./lakehouse")
        .config("spark.sql.shuffle.partitions", "8")   # small = laptop-friendly
        .config("spark.databricks.delta.retentionDurationCheck.enabled", "true")
        .enableHiveSupport()
        .getOrCreate()
    )

    What to look for: inferSchema=False. Landing everything as STRING is a deliberate bronze decision — inference would guess at the mixed timestamp formats and silently null out the 2% that do not match, destroying evidence before you have looked at it. Typing happens at the silver boundary in Lab 3.

    Task 4 — Profile bronze for swamp smells (15 min)¶

    Complete src/masar/ingest/profile_bronze.py:

    # src/masar/ingest/profile_bronze.py
"""Cheap data-profiling pass to surface 'swamp' smells before we trust bronze."""
from __future__ import annotations

import argparse

from pyspark.sql import functions as F

from masar.spark import get_spark

BRONZE = "./lakehouse/bronze"


def profile(table_path: str, key: str | None = None) -> None:
    spark = get_spark("profile-bronze")
    df = spark.read.format("delta").load(table_path)
    n = df.count()
    print(f"\n=== {table_path} ===")
    print(f"rows={n:,}  columns={len(df.columns)}  files={df.rdd.getNumPartitions()}")

    # 1) Null / empty rate per column: a high rate on a key column is a swamp smell.
    #    CSV lands as STRING, so treat '' as missing too.
    exprs = []
    for c in df.columns:
        col = F.col(f"`{c}`")
        missing = F.when(col.isNull() | (col.cast("string") == F.lit("")), 1).otherwise(0)
        exprs.append(F.round(F.sum(missing) / F.lit(n), 4).alias(c))
    print("-- missing rate per column --")
    df.select(exprs).show(truncate=False, vertical=True)

    # 2) Duplicate business keys. Bronze ALLOWS duplicates, but we must SEE them.
    if key and key in df.columns:
        dupes = df.groupBy(key).count().filter("count > 1")
        print(f"duplicate {key} groups: {dupes.count():,}")
        dupes.orderBy(F.desc("count")).show(5, truncate=False)

    # 3) Format drift on timestamp-ish string columns (the 2% defect).
    for c in ("pickup_ts", "dropoff_ts", "hire_date"):
        if c in df.columns:
            iso = df.filter(F.col(c).rlike(r"^\d{4}-\d{2}-\d{2}")).count()
            eu = df.filter(F.col(c).rlike(r"^\d{2}/\d{2}/\d{4}")).count()
            print(f"{c}: iso-like={iso:,}  dd/mm/yyyy-like={eu:,}  other={n - iso - eu:,}")

    # 4) Value-domain surprises on low-cardinality columns.
    for c in ("city", "status", "payment_type", "producer_version"):
        if c in df.columns:
            print(f"-- distinct {c} --")
            df.groupBy(c).count().orderBy(F.desc("count")).show(10, truncate=False)


def main() -> None:
    p = argparse.ArgumentParser()
    p.add_argument("table", help="e.g. bronze/trips")
    p.add_argument("--key", default=None, help="business key to check for duplicates")
    args = p.parse_args()
    profile(f"./lakehouse/{args.table}", key=args.key)


if __name__ == "__main__":
    main()

    Acceptance criteria¶

    • bronze.trips, bronze.gps_events, bronze.drivers all exist as Delta tables at lakehouse/bronze/<table> and are queryable by name (spark.table("bronze.trips"))
    • Every bronze table carries _ingested_at, _source_file and _batch_id
    • Landing is append-only: re-running trips for 2026-06-01 produced 96,400 rows, not 48,200
    • No cleaning, casting, filtering or de-duplication happened at this layer (all source columns still STRING for CSV feeds; GPS payload still a nested struct)
    • The two landings are separable by _batch_id
    • profile_bronze ran on all three tables and its output is captured in LAB1_NOTES.md
    • LAB1_NOTES.md names ≥ 3 swamp risks, each with the evidence line and the layer that will fix it
    • The fragmentation numbers for bronze.gps_events are recorded (baseline for Lab 4 OPTIMIZE)
    • The benchmark table is filled from your own run
    • Commit feat(bronze): land trips/gps/drivers with lineage + profiling exists; lakehouse/ is not in the commit

    Self-check questions¶

    Q1. Bronze now holds 96,400 rows for a day with 48,200 trips. Is this a bug? Justify in medallion terms.

    Answer No. Bronze is an append-only ledger of what *arrived*, not a model of what is *true*. Duplication at bronze is expected and is resolved deterministically at the silver boundary by keeping the latest row per `trip_id` (Lab 3's incremental MERGE). Preventing the duplication by overwriting would destroy the ability to reprocess history, which is the whole reason bronze exists. The duplication is visible and attributable because of `_batch_id`.

    Q2. Why does land_trips set inferSchema=False and land every column as STRING?

    Answer Schema inference would guess types from a sample and silently coerce or null out values that do not fit — precisely the ~2% of rows with `DD/MM/YYYY HH:MM` timestamps and any oddly formatted `fare_sar`. That is data loss disguised as convenience, and it happens *before* anyone has profiled the file. Bronze keeps data as-received; typing is a deliberate, tested transformation at silver where a failure is visible and a quarantine path exists.

    Q3. A colleague proposes "just fix that one bad row" directly in bronze.trips. What do you tell them?

    Answer Bronze is immutable. Editing it breaks reproducibility: the silver table can no longer be rebuilt from raw and the audit chain from a curated value back to its source row is severed. The correction belongs in silver as reproducible logic (a MERGE from a corrections fixture, as in Lab 4), so that the fix is reviewable, re-runnable and visible in the Delta history. If the source itself was wrong, the corrected file is *landed as a new batch*, not swapped in place.

    Q4. What would break downstream if _source_file were not captured?

    Answer Three things. (1) Incident forensics: when a bad batch is discovered you cannot select the rows it produced, so you cannot scope the blast radius or reprocess only the affected window. (2) Audit: you cannot answer "which delivered file produced this number in the regulatory report". (3) Late-arrival analysis: you lose the ability to correlate arrival file with business date, which is exactly the diagnosis path for the Module 3 undercount bug.

    Q5. bronze.gps_events keeps payload as a nested struct rather than flattening lat/lon/speed_kmh into top-level columns. Why is that the right call at bronze — and what future incident does it help you diagnose?

    Answer Flattening is a transformation and belongs at silver; keeping the struct preserves the source document shape exactly as delivered, including any new keys a producer adds. It also keeps `producer_version` next to the payload it describes — which is what lets you diagnose the semantic-drift incident where `producer_version` 2.5.0 emits `speed_kmh` in m/s while 2.4.0 emits km/h. The key and type are unchanged, so schema validation passes; only the version-to-payload correlation reveals it.

    Q6. You need to reprocess six months of trips because a silver derivation was wrong. What in this lab makes that possible, and what would have made it impossible?

    Answer Possible because bronze retained every landed row, untyped and unfiltered, with lineage — so silver can simply be rebuilt from bronze with corrected logic (ELT's core payoff, Module 3). Impossible if landing had used `mode("overwrite")`, dropped malformed rows with `mode("DROPMALFORMED")`, or cleaned at the landing step: in each case the raw evidence no longer exists and only a re-extraction from the source system — which retention policy may forbid — could recover it.
